# 05 求職數據實驗室：Job Search Analytics Dashboard

> **「身為未來的 Data Engineer，你找工作的過程本身，就應該是一個最漂亮的 Data Analytics 專案！」**

非本科轉職者最常見的失敗原因不是「技術不夠」，而是「心理內耗」——投了 20 間沒回音就開始自我懷疑「我是不是不適合寫 code」。

合格的工程師用**數據漏斗（Conversion Funnel）**思考問題：
- 履歷沒人讀？➜ 修訂標題關鍵字與 GitHub 專案亮點。
- 有讀但沒面試？➜ 專案商業價值與技能匹配度不足。
- 一面通過但二面掛？➜ 強化系統架構解釋與 Failure Case。

## 📊 1. 求職轉換漏斗標準 (Conversion Funnel Benchmarks)

```
[ 投遞量 Applications Sent ]  (基準: 每週 15~20 份)
         │  目標轉換率: > 40~50%
         ▼
[ 履歷已讀 Resume Read ]  ── 若過低 ➜ 修改履歷抬頭、精簡排版、強調 B2B 關鍵字
         │  目標轉換率: > 20~25%
         ▼
[ HR 電話訪談 HR Screening ]  ── 若過低 ➜ 調整求職動機、專案亮點 1 分鐘電梯簡報
         │  目標轉換率: > 50%
         ▼
[ 技術面試 Technical Round ]  ── 若過低 ➜ 狂刷 M8 Portfolio Gate、Live SQL、Docker 除錯
         │  目標轉換率: > 25%
         ▼
[ 最終面試 / Offer 簽約 ]  ── 薪資談判、團隊文化適配評估
```

## 🔍 3. 面試題目深度覆盤日誌 (Interview Question Log)

每結束一場技術面試，**走出會議室或關閉 Zoom 的 15 分鐘內**，立刻打開這份紀錄表記錄下所有被問到的問題：

### 覆盤日誌範本

```markdown
### 📝 面試覆盤：[公司名稱] - [職缺名稱] (日期: 2024-XX-XX)

1. **題目記錄**：
   - 題目：如果 API 傳入的 JSON 結構偶爾少一個欄位，你的 Pipeline 會直接 Crash 嗎？你怎麼設計防禦？
   - 技術分類：`[Data Quality / Python Backend]`
   
2. **當下回答狀況**：
   - 當時回答：「我有用 try...except 抓 KeyError。」
   - 自我評估：太被動，面試官看起來不太滿意。

3. **業界標準最佳實務 (複習後的標準答案)**：
   - 應該使用 Pydantic BaseModel 定義 Schema Contract，設定預設值或 Optional 欄位。
   - 在 ETL 層導入 `DataQualityChecker`，將缺漏資料導流至 `quarantine_records`（隔離區）並發出警報，而不是直接讓整個 Pipeline 崩潰或草率跳過。

4. **對應教材補強章節**：
   - [M5: 04_Production工程三件套_冪等性_品質檢查與稽核日誌.md](../05_Month05_Python與資料庫整合自動化/04_Production工程三件套_冪等性_品質檢查與稽核日誌.md)
```

## 🎯 4. 數據驅動的迭代閉環 (Data-Driven Iteration Loop)

```
        ┌────────────────────────────────────────────────────────┐
        ▼                                                        │
[ 穩定投遞 15 份/週 ] ──> [ 參加面試 ] ──> [ 記錄被問問題與弱項 ]  │
                                                  │              │
                                                  ▼              │
                                     [ 週末針對弱項專題刷題 ] ────┘
```

> **心態定錨**：
> 每一場被問倒的面試，都不是「失敗」，而是**取得了一筆高價值的市場回饋數據點**。只要維持這個數據閉環，持續修補 3~5 週，你的面試防禦力將趨近於 100%！

> [!IMPORTANT]
> **求職大數法則 (Law of Large Numbers)**：
> 拿到 Offer 的工程師不是「從不被拒絕的人」，而是「把每一次拒絕都轉化為一次程式碼與架構迭代的人」。當你的投遞基數達到 30~50 家、漏斗完成 3 輪覆盤閉環，錄取 Offer 是數學上的必然結果！
