# 03 日期、字串處理與效能優化入門

> **寫在前面：「骯髒的資料」是資料分析師最大的敵人**
> 在真實工作中，你從系統拿到的資料往往不是整齊的格式：
> - 日期可能是 `'2024/01/15'`（斜線格式），也可能是 `'20240115'`（純數字）
> - 客戶名稱前後有空格、大小寫不一致
> - 地址欄位塞了城市與郵遞區號，需要拆開

> 本篇給你：**完整的 PostgreSQL 日期、字串函數武器庫**，加上**讀懂 EXPLAIN 執行計畫、設計 Index** 的效能優化入門。

## 一、日期函數完整指南

### 1.1 EXTRACT / DATE_PART — 擷取日期元件

```sql
SELECT
    order_date,
    EXTRACT(YEAR   FROM order_date)     AS 年份,
    EXTRACT(MONTH  FROM order_date)     AS 月份,
    EXTRACT(DAY    FROM order_date)     AS 日,
    EXTRACT(QUARTER FROM order_date)    AS 季度,       -- 1, 2, 3, 4
    EXTRACT(DOW    FROM order_date)     AS 星期幾,     -- 0=日, 1=一, ..., 6=六
    EXTRACT(WEEK   FROM order_date)     AS 第幾週,
    EXTRACT(EPOCH  FROM order_date)     AS Unix時間戳  -- 秒數
FROM orders
LIMIT 5;

-- DATE_PART 與 EXTRACT 完全等價，但語法不同：
SELECT DATE_PART('month', order_date) AS 月份 FROM orders LIMIT 3;
```

**常用季度分析**：

```sql
-- 情境：計算各季度業績（常見於財報分析）
SELECT
    EXTRACT(YEAR FROM order_date)::int     AS 年份,
    EXTRACT(QUARTER FROM order_date)::int  AS 季度,
    TO_CHAR(MIN(order_date), 'MM/DD')      AS 季初,
    TO_CHAR(MAX(order_date), 'MM/DD')      AS 季末,
    COUNT(DISTINCT order_id)               AS 訂單數,
    SUM(total_amount)                      AS 季度業績
FROM orders
WHERE status = 'COMPLETED'
GROUP BY 年份, 季度
ORDER BY 年份, 季度;
```

### 1.2 DATE_TRUNC — 截斷到指定精度

`DATE_TRUNC` 是時間序列分析的基礎，它把時間截斷到指定的精度（月/週/季/年），讓你能做 GROUP BY。

```sql
-- DATE_TRUNC 各精度示範
SELECT
    NOW()                                       AS 現在時間,
    DATE_TRUNC('year',    NOW())                AS 截到年初,    -- 2024-01-01 00:00:00
    DATE_TRUNC('quarter', NOW())                AS 截到季初,    -- 2024-07-01 00:00:00
    DATE_TRUNC('month',   NOW())                AS 截到月初,    -- 2024-09-01 00:00:00
    DATE_TRUNC('week',    NOW())                AS 截到週一,    -- 最近的週一
    DATE_TRUNC('day',     NOW())                AS 截到今天零時,
    DATE_TRUNC('hour',    NOW())                AS 截到整點;
```

**月份業績聚合（最常用）**：

```sql
-- 正確做法：先 DATE_TRUNC 再 GROUP BY
SELECT
    DATE_TRUNC('month', order_date)::date AS 月份,
    COUNT(*)                              AS 訂單數,
    SUM(total_amount)                     AS 月業績,
    ROUND(AVG(total_amount), 0)           AS 平均訂單金額
FROM orders
WHERE status = 'COMPLETED'
GROUP BY DATE_TRUNC('month', order_date)
ORDER BY 月份;
```

---

### 1.3 TO_CHAR — 格式化日期輸出

`TO_CHAR` 把日期轉換成你想要的字串格式，常用於報表顯示：

```sql
SELECT
    order_date,
    TO_CHAR(order_date, 'YYYY-MM-DD')          AS 標準格式,       -- 2024-09-15
    TO_CHAR(order_date, 'YYYY年MM月DD日')      AS 中文格式,       -- 2024年09月15日
    TO_CHAR(order_date, 'MM/DD/YYYY')          AS 美式格式,       -- 09/15/2024
    TO_CHAR(order_date, 'Day, DD Mon YYYY')    AS 英文完整格式,   -- Sunday, 15 Sep 2024
    TO_CHAR(order_date, '"Q"Q YYYY')           AS 季度標籤,       -- Q3 2024
    TO_CHAR(total_amount, 'FM$999,999,990.00') AS 金額格式        -- $1,234,567.89
FROM orders
LIMIT 5;
```

**TO_DATE — 把字串解析為日期**：

```sql
-- 情境：從 Excel 匯入的資料，日期是字串格式，需要轉換
SELECT
    TO_DATE('2024/09/15', 'YYYY/MM/DD')     AS 斜線格式,
    TO_DATE('20240915', 'YYYYMMDD')         AS 純數字格式,
    TO_DATE('15-Sep-2024', 'DD-Mon-YYYY')  AS 英文月份;

-- 實際應用：修正格式不一致的訂單日期
UPDATE staging_orders
SET order_date = TO_DATE(raw_date_string, 'YYYY/MM/DD')
WHERE raw_date_string ~ '^\d{4}/\d{2}/\d{2}$';   -- 正規表示式確認格式
```

### 1.4 AGE 與日期計算

```sql
-- AGE：計算兩個日期之間的間隔（以年月日表示）
SELECT
    c.company_name                              AS 客戶名稱,
    c.created_at::date                          AS 客戶建立日期,
    AGE(CURRENT_DATE, c.created_at::date)       AS 合作年資,
    EXTRACT(YEAR FROM AGE(CURRENT_DATE, c.created_at::date))::int AS 合作年數
FROM customers c
WHERE c.status = 'ACTIVE'
ORDER BY c.created_at;

-- 日期加減運算（用 interval）
SELECT
    CURRENT_DATE                                AS 今天,
    CURRENT_DATE + INTERVAL '30 days'          AS 30天後,
    CURRENT_DATE - INTERVAL '1 year'           AS 去年今天,
    CURRENT_DATE + INTERVAL '1 month'          AS 下個月今天,
    CURRENT_DATE - INTERVAL '1 quarter'        AS 上一季今天;

-- 實際應用：找出「90天內即將到期的合約」（假設有 contract_end_date）
SELECT
    company_name,
    contract_end_date,
    contract_end_date - CURRENT_DATE AS 剩餘天數
FROM customers
WHERE status = 'ACTIVE'
  AND contract_end_date BETWEEN CURRENT_DATE AND CURRENT_DATE + INTERVAL '90 days'
ORDER BY contract_end_date;
```

### 1.5 generate_series — 生成日期序列

`generate_series` 是製作完整日曆報表的神器，避免「某天沒有資料就消失」的問題：

```sql
-- 產生 2024 年全年的月份序列
SELECT generate_series(
    '2024-01-01'::date,
    '2024-12-01'::date,
    '1 month'::interval
)::date AS month;

-- 實際應用：確保每個月都有一列（即使沒有業績也顯示 0）
WITH all_months AS (
    SELECT generate_series(
        '2024-01-01'::date,
        '2024-12-01'::date,
        '1 month'::interval
    )::date AS month
),
actual_revenue AS (
    SELECT
        DATE_TRUNC('month', order_date)::date AS month,
        SUM(total_amount)                      AS revenue
    FROM orders
    WHERE status = 'COMPLETED'
      AND EXTRACT(YEAR FROM order_date) = 2024
    GROUP BY DATE_TRUNC('month', order_date)
)
SELECT
    TO_CHAR(m.month, 'YYYY-MM')      AS 月份,
    COALESCE(r.revenue, 0)           AS 業績
FROM all_months m
LEFT JOIN actual_revenue r ON m.month = r.month
ORDER BY m.month;
```

## 二、字串函數完整指南

### 2.1 清理函數：TRIM / UPPER / LOWER / REPLACE

資料清理最常用的三板斧：

```sql
-- 情境：客戶名稱從 CRM 匯入，有大小寫不一致和多餘空格
SELECT
    '  台灣科技有限公司  '                   AS 原始,
    TRIM('  台灣科技有限公司  ')             AS TRIM_去除首尾空白,
    LTRIM('  ABC  ')                        AS LTRIM_只去左邊,
    RTRIM('  ABC  ')                        AS RTRIM_只去右邊,

    UPPER('hello world')                    AS 全大寫,
    LOWER('HELLO WORLD')                    AS 全小寫,
    INITCAP('hello world')                  AS 首字大寫,

    REPLACE('2024/09/15', '/', '-')         AS 取代斜線為破折號,
    REPLACE('NT$1,234,567', ',', '')        AS 移除金額逗號;

-- 實際應用：標準化公司名稱（去空格 + 統一大寫）
UPDATE customers
SET company_name = TRIM(UPPER(company_name))
WHERE company_name != TRIM(UPPER(company_name));
```

---

### 2.2 擷取函數：SUBSTRING / SPLIT_PART / LEFT / RIGHT

```sql
-- SUBSTRING：擷取特定位置的字串
SELECT
    'ORD-2024-001'                            AS 原始,
    SUBSTRING('ORD-2024-001' FROM 5 FOR 4)   AS 擷取年份,     -- 2024
    LEFT('ORD-2024-001', 3)                  AS 左邊3碼,      -- ORD
    RIGHT('ORD-2024-001', 3)                 AS 右邊3碼,      -- 001
    LENGTH('ORD-2024-001')                   AS 字串長度;     -- 12

-- SPLIT_PART：用分隔符切割字串（像 Excel 的文字到欄）
SELECT
    'SRV-001-PRO'                            AS 產品代碼,
    SPLIT_PART('SRV-001-PRO', '-', 1)       AS 第1段,        -- SRV
    SPLIT_PART('SRV-001-PRO', '-', 2)       AS 第2段,        -- 001
    SPLIT_PART('SRV-001-PRO', '-', 3)       AS 第3段;        -- PRO

-- 實際應用：從訂單號碼 ORD-2024-001 拆出年份與序號
SELECT
    order_number,
    SPLIT_PART(order_number, '-', 2)::int AS 訂單年份,
    SPLIT_PART(order_number, '-', 3)::int AS 訂單序號
FROM orders
LIMIT 10;
```

---

### 2.3 組合函數：CONCAT / || / STRING_AGG

```sql
-- 字串合併
SELECT
    CONCAT(s.name, ' (', s.region, ')')      AS 業務_含區域,
    s.name || ' - ' || s.email               AS 業務_含信箱
FROM salespeople s;

-- STRING_AGG：將多列合併為一個字串（類似 GROUP_CONCAT）
-- 情境：列出每個客戶曾購買的所有產品類別
SELECT
    c.company_name,
    STRING_AGG(
        DISTINCT p.category,
        ', ' ORDER BY p.category
    ) AS 購買過的類別
FROM customers c
JOIN orders o     ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p   ON oi.product_id = p.product_id
WHERE o.status = 'COMPLETED'
GROUP BY c.customer_id, c.company_name
ORDER BY c.company_name;
```

---

### 2.4 搜尋：LIKE / ILIKE / POSITION

```sql
-- LIKE：大小寫敏感的模糊搜尋
-- ILIKE：大小寫不敏感（PostgreSQL 特有）
SELECT company_name
FROM customers
WHERE company_name ILIKE '%科技%'        -- 包含「科技」（不分大小寫）
   OR company_name ILIKE 'taiwan%'       -- 以 taiwan 開頭（不分大小寫）
   OR company_name LIKE '%有限公司';     -- 以「有限公司」結尾

-- POSITION：找到子字串的位置（找不到回傳 0）
SELECT
    company_name,
    POSITION('科技' IN company_name) AS 科技二字的位置
FROM customers
WHERE POSITION('科技' IN company_name) > 0;
```

---

### 2.5 正規表示式：REGEXP_REPLACE / REGEXP_MATCHES

```sql
-- 正規表示式取代
SELECT
    -- 移除所有非數字字元（適合清理電話號碼）
    REGEXP_REPLACE('(02) 2345-6789', '[^0-9]', '', 'g') AS 純數字電話,

    -- 移除開頭的數字
    REGEXP_REPLACE('123ABC', '^\d+', '')                AS 去掉開頭數字,

    -- 標準化統一編號格式（確保 8 位數）
    REGEXP_REPLACE('  12345678  ', '\s', '', 'g')       AS 去掉空格;

-- 正規表示式篩選（~ 運算子）
SELECT company_name, tax_id
FROM customers
WHERE tax_id ~ '^\d{8}$'    -- 統一編號必須是 8 位純數字
  AND tax_id IS NOT NULL;

-- REGEXP_MATCHES：擷取符合條件的子字串
SELECT
    product_code,
    (REGEXP_MATCHES(product_code, '[A-Z]+'))[1]   AS 類別代碼,  -- SRV, HW, SW...
    (REGEXP_MATCHES(product_code, '\d+'))[1]       AS 產品序號
FROM products;
```

### 2.6 字串函數組合應用：資料清理實戰

**情境**：從 Excel 匯入的客戶資料有各種格式問題，需要一次性清理：

```sql
-- 建立清理後的 staging 表
SELECT
    customer_id,
    -- 公司名稱：去空格、移除多餘特殊符號
    TRIM(REGEXP_REPLACE(company_name, '\s+', ' ', 'g'))
                                                    AS clean_company_name,

    -- 統一編號：移除所有非數字、確保 8 位
    CASE
        WHEN LENGTH(REGEXP_REPLACE(tax_id, '[^0-9]', '', 'g')) = 8
        THEN REGEXP_REPLACE(tax_id, '[^0-9]', '', 'g')
        ELSE NULL  -- 格式錯誤的標記為 NULL，等待人工確認
    END                                             AS clean_tax_id,

    -- 產業別：統一為大寫
    UPPER(TRIM(industry))                           AS clean_industry,

    -- 城市：移除郵遞區號（如 "100 台北市" → "台北市"）
    TRIM(REGEXP_REPLACE(city, '^\d{3,6}\s*', ''))  AS clean_city,

    -- 標記是否需要人工複查
    CASE
        WHEN tax_id IS NULL OR LENGTH(REGEXP_REPLACE(tax_id, '[^0-9]', '', 'g')) != 8
        THEN TRUE
        ELSE FALSE
    END                                             AS needs_review
FROM staging_customers;
```

## 三、效能優化入門：讀懂 EXPLAIN

### 3.1 為什麼要關心效能？

同一個查詢需求，寫法不同，效能可能差 **100 倍以上**。在生產環境的報表系統或儀表板中，一個慢查詢會讓所有使用者都在等待。

---

### 3.2 EXPLAIN vs EXPLAIN ANALYZE

```sql
-- EXPLAIN：只顯示「計畫」，不真正執行
-- 用途：安全地預覽查詢計畫，不會改動資料
EXPLAIN
SELECT * FROM orders WHERE customer_id = 42;

-- EXPLAIN ANALYZE：真正執行並顯示「實際執行時間」
-- 用途：測量實際效能，找出瓶頸
EXPLAIN ANALYZE
SELECT * FROM orders WHERE customer_id = 42;

-- 加上 BUFFERS：顯示記憶體緩衝區使用情況
EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT)
SELECT
    c.company_name,
    SUM(o.total_amount)
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
WHERE o.status = 'COMPLETED'
GROUP BY c.company_name;
```

---

### 3.3 讀懂 EXPLAIN 輸出

```
EXPLAIN 輸出範例：
-----------------------------------------------------------------------------------
Hash Join  (cost=125.42..3258.19 rows=5234 width=64)
             (actual time=12.345..89.123 rows=5190 loops=1)
  Hash Cond: (o.customer_id = c.customer_id)
  ->  Seq Scan on orders o                         ← 全表掃描！（可能的瓶頸）
        (cost=0.00..2800.00 rows=75000 width=32)
        Filter: (status = 'COMPLETED')
        Rows Removed by Filter: 12300              ← 過濾掉 12300 列
  ->  Hash  (cost=98.00..98.00 rows=2194 width=32)
        ->  Seq Scan on customers c
              (cost=0.00..98.00 rows=2194 width=32)
Planning Time: 1.234 ms
Execution Time: 89.456 ms                          ← 重點：實際執行時間
```

**關鍵指標解讀**：

| 指標 | 說明 | 警示信號 |
|------|------|---------|
| `Seq Scan` | 全表掃描，逐列讀取 | 大表上的 Seq Scan → 考慮加 Index |
| `Index Scan` | 使用索引 | 一般情況下的良好信號 |
| `Bitmap Index Scan` | 批次使用索引 | 中等效能 |
| `Hash Join` | 雜湊連結 | 適合大表 JOIN |
| `Nested Loop` | 巢狀迴圈 | 小表 JOIN 效率佳，大表慢 |
| `actual time=X..Y` | 開始到結束的毫秒數 | Y > 1000ms 需要優化 |
| `rows=N` | 實際回傳的列數 | 若 estimate 和 actual 差太多 → 需要 ANALYZE |

### 3.4 常見慢查詢原因與修正

#### 原因 1：在 WHERE 子句中對欄位做運算（破壞 Index）

```sql
-- ❌ 慢：對 order_date 做函數運算，無法使用 Index
WHERE EXTRACT(YEAR FROM order_date) = 2024

-- ✅ 快：改為範圍條件，可使用 Index
WHERE order_date >= '2024-01-01' AND order_date < '2025-01-01'

-- ❌ 慢：對 total_amount 做運算
WHERE total_amount * 1.05 > 100000

-- ✅ 快：把計算移到右邊
WHERE total_amount > 100000 / 1.05
```

#### 原因 2：SELECT * 取回不需要的欄位

```sql
-- ❌ 慢：取回所有欄位（包含可能的 TEXT/BLOB 欄位）
SELECT * FROM orders WHERE customer_id = 42;

-- ✅ 快：只取需要的欄位
SELECT order_id, order_number, order_date, total_amount
FROM orders
WHERE customer_id = 42;
```

#### 原因 3：JOIN 順序不佳

```sql
-- ❌ 可能較慢：先 JOIN 大表，再過濾
SELECT * FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
WHERE c.city = '台北市';

-- ✅ 較快：先過濾小表，再 JOIN（PostgreSQL 最佳化器通常會自動處理，但明確寫出更好）
WITH taipei_customers AS (
    SELECT customer_id FROM customers WHERE city = '台北市'
)
SELECT o.*
FROM orders o
JOIN taipei_customers tc ON o.customer_id = tc.customer_id;
```

### 3.5 Index 設計原則

**什麼是 Index？**

Index 就像書本的目錄，讓資料庫不用從第一頁掃到最後一頁，直接跳到對的位置。代價是：**寫入變慢、佔用額外儲存空間**。

**建立 Index 的語法**：

```sql
-- 基本單欄 Index
CREATE INDEX idx_orders_customer_id ON orders(customer_id);

-- 複合 Index（欄位順序很重要！）
CREATE INDEX idx_orders_status_date ON orders(status, order_date);

-- 部分 Index（只對滿足條件的列建立索引，更省空間）
CREATE INDEX idx_orders_completed_date
ON orders(order_date)
WHERE status = 'COMPLETED';

-- 唯一 Index（同時強制唯一性）
CREATE UNIQUE INDEX idx_customers_tax_id
ON customers(tax_id)
WHERE tax_id IS NOT NULL;

-- 查看表上有哪些 Index
SELECT indexname, indexdef
FROM pg_indexes
WHERE tablename = 'orders';
```

---

### 3.6 Index 設計決策樹

```
需不需要建 Index？

這個欄位有多少「獨特值」（Cardinality）？
  ├── 很少（如：status 只有 3 種值）→ Cardinality 低 → Index 效果差，考慮「部分 Index」
  └── 很多（如：customer_id、order_number）→ Cardinality 高 → 強烈建議建 Index

這個欄位在 WHERE / JOIN ON / ORDER BY 中頻繁出現嗎？
  ├── 是 → 建議建 Index
  └── 否 → 暫時不建

這張表的讀寫比例？
  ├── 讀多寫少（報表查詢）→ Index 越多越好
  └── 寫多讀少（交易系統）→ Index 謹慎添加，每個 Index 都會拖慢 INSERT/UPDATE
```

**常見的 Index 應用場景**：

```sql
-- orders 表的常用 Index 設計
CREATE INDEX idx_orders_customer_id  ON orders(customer_id);       -- JOIN
CREATE INDEX idx_orders_salesperson  ON orders(salesperson_id);    -- JOIN
CREATE INDEX idx_orders_status_date  ON orders(status, order_date); -- WHERE + ORDER BY
CREATE INDEX idx_orders_date         ON orders(order_date);        -- 時間範圍查詢

-- customers 表
CREATE INDEX idx_customers_industry  ON customers(industry);
CREATE INDEX idx_customers_city      ON customers(city);
CREATE UNIQUE INDEX idx_customers_tax ON customers(tax_id) WHERE tax_id IS NOT NULL;
```

### 3.7 ANALYZE — 更新統計資訊

PostgreSQL 的查詢計畫器依賴**統計資訊**來估算每個查詢的成本。若資料大量更新後沒有重新統計，計畫器可能做出錯誤判斷：

```sql
-- 對單一表格更新統計資訊
ANALYZE orders;

-- 對整個資料庫更新統計資訊（通常由 autovacuum 自動處理）
ANALYZE;

-- VACUUM ANALYZE：同時清理死列和更新統計
VACUUM ANALYZE orders;
```

## 四、綜合練習題（5 題）

---

### 題目 1：最近 30 天 vs 上個月 30 天的業績比較

**需求**：財務主管想快速比較最近 30 天和前 30 天的業績，並計算環比變化。

```sql
-- 解答
WITH recent AS (
    SELECT SUM(total_amount) AS revenue
    FROM orders
    WHERE status = 'COMPLETED'
      AND order_date >= CURRENT_DATE - INTERVAL '30 days'
),
previous AS (
    SELECT SUM(total_amount) AS revenue
    FROM orders
    WHERE status = 'COMPLETED'
      AND order_date >= CURRENT_DATE - INTERVAL '60 days'
      AND order_date <  CURRENT_DATE - INTERVAL '30 days'
)
SELECT
    r.revenue                               AS 近30天業績,
    p.revenue                               AS 前30天業績,
    ROUND(r.revenue - p.revenue, 0)         AS 差額,
    ROUND((r.revenue - p.revenue) / p.revenue * 100, 1) AS 環比成長率
FROM recent r, previous p;
```

---

### 題目 2：找出訂單號碼格式異常的資料

**需求**：訂單號碼應為 `ORD-YYYY-NNN` 格式（如 ORD-2024-001），找出不符合此格式的異常訂單。

```sql
-- 解答
SELECT
    order_id,
    order_number,
    '格式應為 ORD-YYYY-NNN' AS 問題描述
FROM orders
WHERE order_number !~ '^ORD-\d{4}-\d{3,}$'   -- 正規表示式：不符合標準格式
ORDER BY order_id;
```

---

### 題目 3：各月份業績報表（含月份名稱、季度標籤）

**需求**：輸出包含中文月份名稱、季度標籤的業績摘要表。

```sql
-- 解答
SELECT
    TO_CHAR(DATE_TRUNC('month', order_date), 'YYYY年MM月')   AS 月份,
    'Q' || EXTRACT(QUARTER FROM order_date)::text             AS 季度,
    COUNT(DISTINCT order_id)                                  AS 訂單數,
    SUM(total_amount)                                         AS 業績,
    ROUND(AVG(total_amount), 0)                               AS 平均訂單金額,
    MAX(total_amount)                                         AS 最大單筆金額
FROM orders
WHERE status = 'COMPLETED'
GROUP BY DATE_TRUNC('month', order_date), EXTRACT(QUARTER FROM order_date)
ORDER BY DATE_TRUNC('month', order_date);
```

### 題目 4：客戶合作年資分析

**需求**：根據客戶建立日期，計算合作年資，並分類為「新客戶/成長客戶/成熟客戶/老客戶」。

```sql
-- 解答（假設 customers 表有 created_at 欄位）
SELECT
    company_name,
    created_at::date                                            AS 合作開始日,
    EXTRACT(YEAR FROM AGE(CURRENT_DATE, created_at::date))::int AS 合作年數,
    AGE(CURRENT_DATE, created_at::date)                         AS 合作時長,
    CASE
        WHEN EXTRACT(YEAR FROM AGE(CURRENT_DATE, created_at::date)) < 1
        THEN '🌱 新客戶 (<1年)'
        WHEN EXTRACT(YEAR FROM AGE(CURRENT_DATE, created_at::date)) < 3
        THEN '📈 成長客戶 (1-3年)'
        WHEN EXTRACT(YEAR FROM AGE(CURRENT_DATE, created_at::date)) < 5
        THEN '💼 成熟客戶 (3-5年)'
        ELSE '🏆 老客戶 (5年以上)'
    END                                                         AS 客戶成熟度
FROM customers
WHERE status = 'ACTIVE'
ORDER BY created_at;
```

### 題目 5：STRING_AGG 生成客戶購買清單報表

**需求**：產生一份「客戶 × 購買過的產品」報表，每位客戶一列，購買的產品名稱以逗號分隔。

```sql
-- 解答
SELECT
    c.company_name                                              AS 客戶名稱,
    c.industry                                                  AS 產業,
    COUNT(DISTINCT o.order_id)                                  AS 訂單總數,
    SUM(o.total_amount)                                         AS 總購買金額,
    COUNT(DISTINCT p.product_id)                                AS 購買品項數,
    STRING_AGG(DISTINCT p.product_name, ', ' ORDER BY p.product_name)
                                                                AS 購買過的產品
FROM customers c
JOIN orders o     ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p   ON oi.product_id = p.product_id
WHERE o.status = 'COMPLETED'
  AND c.status = 'ACTIVE'
GROUP BY c.customer_id, c.company_name, c.industry
ORDER BY 總購買金額 DESC;
```

## 五、本章重點彙整

```
日期函數
  EXTRACT(part FROM date)     → 擷取年/月/日/季/週
  DATE_TRUNC('month', date)   → 截斷到月初（GROUP BY 月份必備）
  TO_CHAR(date, 'format')     → 格式化輸出（報表顯示）
  TO_DATE(str, 'format')      → 字串解析為日期（資料匯入）
  AGE(date1, date2)           → 計算時間差（年月日形式）
  generate_series(start, end, interval) → 生成連續日期序列

字串函數
  TRIM / LTRIM / RTRIM        → 去空格
  UPPER / LOWER / INITCAP     → 大小寫轉換
  REPLACE(str, from, to)      → 字串取代
  SPLIT_PART(str, delim, n)   → 用分隔符切割
  CONCAT / ||                 → 字串合併
  STRING_AGG(col, sep ORDER BY ...) → 多列合併為一字串
  REGEXP_REPLACE(str, pattern, replacement, flags) → 正規表示式取代

效能優化
  EXPLAIN ANALYZE             → 查看實際執行計畫與時間
  Seq Scan = 全表掃描         → 大表上出現需考慮 Index
  WHERE 子句不要對欄位做計算  → 會破壞 Index
  CREATE INDEX                → 針對 WHERE/JOIN/ORDER BY 欄位
  部分 Index WHERE status='X' → 只對特定值建立索引，更省空間
  ANALYZE                     → 更新統計資訊，讓計畫器做對決定
```
