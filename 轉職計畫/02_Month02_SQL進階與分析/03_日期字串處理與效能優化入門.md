# 03 日期字串處理與查詢效能優化入門

## 一、PostgreSQL 常用日期與時間處理

在企業分析中，超過 70% 的報表都跟「時間維度」有關（按月、按季、計算留存天數）：

```sql
-- 1. 截斷到指定粒度 (DATE_TRUNC)
SELECT DATE_TRUNC('month', CURRENT_DATE); -- 輸出: 2026-08-01 00:00:00

-- 2. 時間加減運算 (INTERVAL)
SELECT CURRENT_DATE - INTERVAL '3 months'; -- 三個月前的日期

-- 3. 計算兩者間距 (AGE 或 日期直接相減)
SELECT AGE('2026-08-31', '2024-01-15'); -- 輸出: 2 years 7 mons 16 days
SELECT CURRENT_DATE - '2026-08-01'::DATE AS days_diff; -- 輸出差距天數: 30

-- 4. 提取年月日週 (EXTRACT)
SELECT 
    EXTRACT(YEAR FROM order_date) AS order_year,
    EXTRACT(QUARTER FROM order_date) AS order_quarter,
    EXTRACT(DOW FROM order_date) AS day_of_week; -- 0: Sunday, 1: Monday...
```

## 二、字串清洗與正規表達式處理

```sql
-- 1. 去除首尾空白 (TRIM)
SELECT TRIM('  Apex Tech  ');

-- 2. 擷取統編或代碼前綴 (SPLIT_PART / SUBSTRING)
SELECT SPLIT_PART('SRV-001-TW', '-', 1); -- 輸出: 'SRV'

-- 3. 隱藏機密資訊（資料脫敏 Masking）
SELECT 
    company_name,
    CONCAT(SUBSTRING(tax_id FROM 1 FOR 4), '****') AS masked_tax_id
FROM customers;
```

## 三、查詢效能優化入門：EXPLAIN ANALYZE 與索引避坑

當資料庫有 100 萬筆以上資料時，不良的 SQL 會讓查詢從 0.05 秒暴增到 30 秒。

### 1. 使用 `EXPLAIN ANALYZE` 讀取執行計畫
在任何查詢前加上 `EXPLAIN (ANALYZE, BUFFERS)`：
```sql
EXPLAIN ANALYZE 
SELECT * FROM orders WHERE customer_id = 105;
```
重點觀察兩個指標：
- **Seq Scan (全表掃描)**：資料庫一頁一頁硬找，資料量大時極慢。
- **Index Scan / Bitmap Index Scan (索引掃描)**：透過 B-Tree 快速定位，速度極快。

### 2. 三大常見「破壞索引」的錯誤寫法

| ❌ 破壞索引的寫法（導致 Seq Scan） | ✅ 能正常使用索引的高效寫法 |
| :--- | :--- |
| `WHERE TO_CHAR(order_date, 'YYYY') = '2024'`<br>（對索引欄位使用函數） | `WHERE order_date >= '2024-01-01' AND order_date < '2025-01-01'` |
| `WHERE company_name LIKE '%Tech'`<br>（左側帶 `%` 萬用字元無法利用 B-Tree） | 改用全文檢索 (`GIN` 索引 + `tsvector`) 或前綴搜尋 `LIKE 'Tech%'` |
| `WHERE amount + 100 > 500`<br>（在欄位上進行數學運算） | `WHERE amount > 400`（將運算移至常數側） |
