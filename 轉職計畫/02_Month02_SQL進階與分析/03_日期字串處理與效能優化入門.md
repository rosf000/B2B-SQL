## 一、日期函數完整指南

> 🎯 **這一節最重要的一件事（心智定位）**：
> 時間是商業分析的第一維度；掌握日期截斷（`DATE_TRUNC`）與元件擷取（`EXTRACT`），就能任意切換年、季、月、週的同環比視角。
>
> 💼 **為什麼非學不可（避坑痛點）**：
> 商業數據 90% 都是時間序列。如果不會日期函數，面對「2024年Q3業績」這種基礎需求，你就只能手寫落落長的字串模糊比對，遇到跨年跨月或閏年時計算必定破產。

### 1.1 EXTRACT / DATE_PART — 擷取日期時間元件

#### 1. 語法結構與參數說明

從時間戳記或日期欄位中，精準抽取出特定的時間單位（如年、月、日、季度、週數、秒數等）。

```sql
-- ANSI SQL 標準語法（推薦，跨多數資料庫通用）
EXTRACT(field FROM source)

-- PostgreSQL 專用擴充函數（與 EXTRACT 功能等價）
DATE_PART('field', source)
```

| 參數 | 型別 | 說明 |
| :--- | :--- | :--- |
| `field` | 識別代號 / 字串 | 要擷取的日期元件名稱（`EXTRACT` 不加單引號；`DATE_PART` 須以單引號包裹，如 `'month'`）。 |
| `source` | `DATE` / `TIMESTAMP` / `INTERVAL` | 被擷取的日期時間來源值。 |
| **回傳值** | `NUMERIC` (PG 14+) / `DOUBLE PRECISION` | 回傳數值。若需進行整數比對或 GROUP BY，建議明確轉型為 `::int`。 |

#### 2. 常用 `field` 欄位代碼表

| 欄位代碼 (`field`) | 說明 | 數值範圍 / 格式 | 商業分析應用場景 |
| :--- | :--- | :--- | :--- |
| `YEAR` | 年份 | 4 位數，例如 `2024` | 跨年財報分組、年度業績比較 |
| `QUARTER` | 季度 | `1` ~ `4` | 季報彙總、同環比分析 |
| `MONTH` | 月份 | `1` ~ `12` | 季節性趨勢、月報表 |
| `DAY` | 每月第幾日 | `1` ~ `31` | 月中結算、對帳週期 |
| `DOW` | 星期幾（日=0） | `0` (週日) ~ `6` (週六) | 門市客流週末效應分析 |
| `ISODOW` | ISO 星期幾（一=1） | `1` (週一) ~ `7` (週日) | 符合工時與 ISO 標準週之排班分析 |
| `WEEK` | ISO 週數 | `1` ~ `53` | 零售供應鏈週進銷存 |
| `DOY` | 當年第幾天 | `1` ~ `366` | 年累計（YTD）推進進度 |
| `EPOCH` | Unix 時間戳記 | 自 1970-01-01 起累計秒數 | 系統日誌關聯、API 對接 |

#### 3. 語法示範與實戰範例

```sql
SELECT
    order_date,
    EXTRACT(YEAR   FROM order_date)::int AS 年份,
    EXTRACT(MONTH  FROM order_date)::int AS 月份,
    EXTRACT(DAY    FROM order_date)::int AS 日,
    EXTRACT(QUARTER FROM order_date)::int AS 季度,       -- 1, 2, 3, 4
    EXTRACT(DOW    FROM order_date)::int AS 星期幾,     -- 0=日, 1=一, ..., 6=六
    EXTRACT(WEEK   FROM order_date)::int AS 第幾週,
    EXTRACT(EPOCH  FROM order_date)      AS Unix時間戳  -- 秒數
FROM orders
LIMIT 5;

-- DATE_PART 與 EXTRACT 完全等價，但語法不同（第一個參數為字串）：
SELECT DATE_PART('month', order_date)::int AS 月份 FROM orders LIMIT 3;
```

**常用季度分析**：

```sql
-- 情境：計算各季度業績（常見於財報分析）
SELECT
    EXTRACT(YEAR FROM order_date)::int     AS 年份,
    EXTRACT(QUARTER FROM order_date)::int  AS 季度,
    TO_CHAR(MIN(order_date), 'MM/DD')      AS 季初,
    TO_CHAR(MAX(order_date), 'MM/DD')      AS 季末,
    COUNT(DISTINCT order_id)               AS 訂單數,
    SUM(total_amount)                      AS 季度業績
FROM orders
WHERE status = 'COMPLETED'
GROUP BY 年份, 季度
ORDER BY 年份, 季度;
```

### 1.2 DATE_TRUNC — 截斷到指定精度（時間序列分析骨架）

#### 1. 語法結構與參數說明

`DATE_TRUNC` 是商業時間序列分析的最核心函數。它會將時間「對齊」至指定精度的起點（例如將 `2024-09-15 14:35:20` 對齊為月初 `2024-09-01 00:00:00`），使得同一個時間區間內的事件具備完全相同的時間戳記，進而能夠進行 `GROUP BY` 聚合。

```sql
DATE_TRUNC('precision', source [, time_zone])
```

| 參數 | 型別 | 說明 |
| :--- | :--- | :--- |
| `'precision'` | `VARCHAR` | 截斷的目標時間單位字串（**必須加單引號**，不區分大小寫）。 |
| `source` | `TIMESTAMP` / `TIMESTAMPTZ` / `INTERVAL` | 要被截斷的時間值。若傳入 `DATE`，PostgreSQL 會隱式轉型為 `TIMESTAMP`。 |
| `time_zone` | `VARCHAR` (選用) | 指定時區（如 `'Asia/Taipei'`），通常在跨時區資料時使用。 |
| **回傳值** | `TIMESTAMP` / `TIMESTAMPTZ` | 回傳截斷後的完整時間戳記（精度以下的時間單位歸零）。 |

> 💡 **嚴謹細節**：因為 `DATE_TRUNC` 回傳的是包含時分秒的時間戳記（如 `2024-09-01 00:00:00`），在只關注日期的聚合報表中，通常會加上 `::date` 轉型為純日期，畫面清爽且節省儲存開銷。

#### 2. 常用截斷精度 (`precision`) 對照表

| 精度字串 | 截斷對齊基準點 | 示範時間：`2024-09-15 14:35:20` 截斷結果 |
| :--- | :--- | :--- |
| `'year'` | 當年 1 月 1 日 00:00:00 | `2024-01-01 00:00:00` |
| `'quarter'` | 該季首月 1 日 00:00:00 (Q3 為 7/1) | `2024-07-01 00:00:00` |
| `'month'` | 當月 1 日 00:00:00 | `2024-09-01 00:00:00` |
| `'week'` | 該週**星期一** 00:00:00 (ISO 週起始日) | `2024-09-09 00:00:00` |
| `'day'` | 當日 00:00:00 | `2024-09-15 00:00:00` |
| `'hour'` | 當小時整點 00:00 | `2024-09-15 14:00:00` |

#### 3. 語法示範與實戰範例

```sql
-- DATE_TRUNC 各精度示範
SELECT
    NOW()                                       AS 現在時間,
    DATE_TRUNC('year',    NOW())                AS 截到年初,    -- 2024-01-01 00:00:00
    DATE_TRUNC('quarter', NOW())                AS 截到季初,    -- 2024-07-01 00:00:00
    DATE_TRUNC('month',   NOW())                AS 截到月初,    -- 2024-09-01 00:00:00
    DATE_TRUNC('week',    NOW())                AS 截到週一,    -- 最近的週一
    DATE_TRUNC('day',     NOW())                AS 截到今天零時,
    DATE_TRUNC('hour',    NOW())                AS 截到整點;
```

**月份業績聚合（最常用）**：

```sql
-- 正確做法：先 DATE_TRUNC 再 GROUP BY
SELECT
    DATE_TRUNC('month', order_date)::date AS 月份,
    COUNT(*)                              AS 訂單數,
    SUM(total_amount)                     AS 月業績,
    ROUND(AVG(total_amount), 0)           AS 平均訂單金額
FROM orders
WHERE status = 'COMPLETED'
GROUP BY DATE_TRUNC('month', order_date)
ORDER BY 月份;
```

### 1.3 TO_CHAR 與 TO_DATE — 日期格式化與字串解析

#### 1. 語法結構與參數說明

在實務中，資料庫內部通常存儲標準的 `TIMESTAMP` 或 `DATE`，但對外呈現報表或接收外部匯入（如 Excel/CSV 髒文字）時，必須在「日期型別」與「格式化字串」之間雙向轉換。

```sql
-- 1. 日期/數值 → 格式化字串（用於前台報表顯示）
TO_CHAR(value, 'format_pattern')

-- 2. 字串 → 日期型別（用於解析匯入的文字日期）
TO_DATE(string_text, 'format_pattern')

-- 3. 字串 → 時間戳記型別（含時分秒）
TO_TIMESTAMP(string_text, 'format_pattern')
```

| 參數 | 型別 | 說明 |
| :--- | :--- | :--- |
| `value` | `DATE` / `TIMESTAMP` / `NUMERIC` | 要被格式化的來源數值或日期。 |
| `string_text` | `VARCHAR` / `TEXT` | 待解析的文字字串。 |
| `'format_pattern'` | `TEXT` | 格式模版字串（區分大小寫代碼，自訂字串需用雙引號 `""` 包裹）。 |

#### 2. 常用格式化模版代碼表

| 模版代碼 | 說明 | 範例與輸出 |
| :--- | :--- | :--- |
| `YYYY` / `YY` | 4 位數年份 / 2 位數年份 | `TO_CHAR(NOW(), 'YYYY')` → `'2024'` |
| `MM` | 2 位數月份（01 ~ 12） | `TO_CHAR(NOW(), 'MM')` → `'09'` |
| `DD` | 2 位數當月日（01 ~ 31） | `TO_CHAR(NOW(), 'DD')` → `'15'` |
| `HH24` / `HH12` | 24 小時制 / 12 小時制（00~23 / 01~12）| `'14'` / `'02'` |
| `MI` | 分鐘（00 ~ 59，**注意不可寫成 MM**） | `TO_CHAR(NOW(), 'MI')` → `'35'` |
| `SS` | 秒數（00 ~ 59） | `TO_CHAR(NOW(), 'SS')` → `'20'` |
| `Day` / `Dy` | 星期幾完整名稱 / 簡稱 | `'Sunday'` / `'Sun'` |
| `"文字"` | 雙引號保留自訂純文字 | `TO_CHAR(NOW(), 'YYYY"年"MM"月"')` → `'2024年09月'` |
| `FM` | Fill Mode（去除前導空格或補零） | `TO_CHAR(1234.5, 'FM$999,990.00')` → `'$1,234.50'` |

#### 3. 語法示範與實戰範例

```sql
SELECT
    order_date,
    TO_CHAR(order_date, 'YYYY-MM-DD')          AS 標準格式,       -- 2024-09-15
    TO_CHAR(order_date, 'YYYY年MM月DD日')      AS 中文格式,       -- 2024年09月15日
    TO_CHAR(order_date, 'MM/DD/YYYY')          AS 美式格式,       -- 09/15/2024
    TO_CHAR(order_date, 'Day, DD Mon YYYY')    AS 英文完整格式,   -- Sunday, 15 Sep 2024
    TO_CHAR(order_date, '"Q"Q YYYY')           AS 季度標籤,       -- Q3 2024
    TO_CHAR(total_amount, 'FM$999,999,990.00') AS 金額格式        -- $1,234,567.89
FROM orders
LIMIT 5;

-- TO_DATE — 把字串解析為日期：
SELECT
    TO_DATE('2024/09/15', 'YYYY/MM/DD')     AS 斜線格式,
    TO_DATE('20240915', 'YYYYMMDD')         AS 純數字格式,
    TO_DATE('15-Sep-2024', 'DD-Mon-YYYY')  AS 英文月份;

-- 實際應用：修正格式不一致的訂單日期
UPDATE staging_orders
SET order_date = TO_DATE(raw_date_string, 'YYYY/MM/DD')
WHERE raw_date_string ~ '^\d{4}/\d{2}/\d{2}$';   -- 正規表示式確認格式
```

### 1.4 AGE 與日期加減計算（時間維度計算庫）

#### 1. 語法結構與參數說明

PostgreSQL 提供了強大的 `INTERVAL` 型別與專屬函數 `AGE()`，能夠精確計算兩個時間點之間的差距，並以人類直覺的年、月、日複合結構回傳。

```sql
-- 雙參數：計算 timestamp1 與 timestamp2 的精確年資/時差（timestamp1 減去 timestamp2）
AGE(timestamp1, timestamp2)

-- 單參數：等價於 AGE(CURRENT_DATE, timestamp)，專門計算年資、年齡
AGE(timestamp)
```

| 參數 | 型別 | 說明 |
| :--- | :--- | :--- |
| `timestamp1`, `timestamp2` | `TIMESTAMP` / `DATE` | 比較的兩個時間點。回傳值為 `INTERVAL`（例如 `3 years 4 mons 12 days`）。 |

> 💡 **跨資料庫對照**：MySQL 請改用 `TIMESTAMPDIFF(YEAR, d1, d2)`；SQL Server 請用 `DATEDIFF(year, d1, d2)`。

#### 2. SQL 日期運算四則規則表

在 SQL 中進行時間位移與天數差距時，遵守以下型別運算規則：

| 運算式範例 | 意義 | 結果型別 | 範例結果 |
| :--- | :--- | :--- | :--- |
| `date + integer` | 日期加上 N 天 | `DATE` | `'2024-01-01'::date + 7` → `2024-01-08` |
| `date - integer` | 日期減去 N 天 | `DATE` | `'2024-01-08'::date - 7` → `2024-01-01` |
| `date - date` | 計算兩日期間相差的天數 | `INTEGER` | `'2024-01-15'::date - '2024-01-01'::date` → `14` |
| `date + interval` | 日期加上時間間隔 | `TIMESTAMP` | `CURRENT_DATE + INTERVAL '1 month'` |
| `timestamp - timestamp` | 計算精確的時間間隔 | `INTERVAL` | 回傳詳細時分秒日期的間隔物件 |

> ⚠️ **避坑細節**：PostgreSQL 的 `INTERVAL` 支援 `'1 year'`, `'3 months'`, `'30 days'` 等單位，但**不支援直接寫 `'1 quarter'`**！若要位移一季，請寫 `INTERVAL '3 months'`。

#### 3. 語法示範與實戰範例

```sql
-- AGE 實測：業務員到職年資（salespeople 有 2020~2024 真實到職日，可立即執行）
SELECT
    salesperson_id,
    name                                                          AS 業務員姓名,
    region                                                        AS 地區,
    hire_date                                                     AS 到職日,
    AGE(CURRENT_DATE, hire_date)                                  AS 到職年資,   -- 例如: 3 years 7 mons 5 days
    EXTRACT(YEAR FROM AGE(CURRENT_DATE, hire_date))::int          AS 到職滿幾年,
    EXTRACT(MONTH FROM AGE(CURRENT_DATE, hire_date))::int         AS 不滿年的月數
FROM salespeople
ORDER BY hire_date;

-- 客戶合作年資
SELECT
    c.company_name                                                AS 客戶名稱,
    c.created_at::date                                            AS 客戶建立日期,
    AGE(CURRENT_DATE, c.created_at::date)                         AS 合作年資,
    EXTRACT(YEAR FROM AGE(CURRENT_DATE, c.created_at::date))::int AS 合作年數
FROM customers c
ORDER BY c.created_at;

-- INTERVAL 日期加減示範
SELECT
    CURRENT_DATE                               AS 今天,
    CURRENT_DATE + INTERVAL '30 days'          AS "30天後",
    CURRENT_DATE - INTERVAL '1 year'           AS 去年今天,
    CURRENT_DATE + INTERVAL '1 month'          AS 下個月今天,
    CURRENT_DATE - INTERVAL '3 months'         AS 上一季今天;  -- PostgreSQL interval 不支援 quarter，請使用 3 months
```

**商業實戰：找出 90 天內即將到期的合約**：

```sql
-- 寫法 A：CTE 動態模擬合約到期日（免改資料表結構，立即可跑）
-- 假設每位客戶合約為建立日起展延 2 年
WITH customer_contracts AS (
    SELECT
        company_name,
        created_at::date AS start_date,
        (created_at::date + INTERVAL '2 years')::date AS contract_end_date
    FROM customers
)
SELECT
    company_name,
    start_date                                 AS 合約起日,
    contract_end_date                          AS 合約到期日,
    contract_end_date - CURRENT_DATE           AS 剩餘天數
FROM customer_contracts
WHERE contract_end_date >= CURRENT_DATE
ORDER BY contract_end_date;

-- 寫法 B：正式新增欄位至資料表（選用）
ALTER TABLE customers ADD COLUMN IF NOT EXISTS contract_end_date DATE;
UPDATE customers
SET contract_end_date = CURRENT_DATE + (customer_id * 15 || ' days')::interval;

SELECT
    company_name,
    contract_end_date,
    contract_end_date - CURRENT_DATE AS 剩餘天數
FROM customers
WHERE contract_end_date BETWEEN CURRENT_DATE AND CURRENT_DATE + INTERVAL '90 days'
ORDER BY contract_end_date;
```

### 1.5 generate_series — 生成日期序列（報表日曆骨架與零值補洞）

#### 1. 語法結構與參數說明

在資料分析實務中，若某天/某月沒有任何訂單，單純對業務表做 `GROUP BY` 會導致這些無業績的日期「在結果集中直接消失」。為解決斷點問題，資料工程的標準做法是使用 `generate_series` 建立連續不中斷的**日曆骨架（Calendar Spine）**，再以 `LEFT JOIN` 關聯真實業務資料，並以 `COALESCE(revenue, 0)` 補零。

```sql
generate_series(start, stop, step_interval)
```

| 參數 | 型別 | 說明 |
| :--- | :--- | :--- |
| `start` | `DATE` / `TIMESTAMP` | 序列起始值（包含邊界）。 |
| `stop` | `DATE` / `TIMESTAMP` | 序列結束值（包含邊界，閉區間 $[start, stop]$）。 |
| `step_interval` | `INTERVAL` | 步進間隔單位，如 `'1 day'::interval` 或 `'1 month'::interval`。 |
| **回傳值** | `SETOF TIMESTAMP` | 產生一系列連續的時間戳記資料列（Table-like 集合）。 |

#### 2. 語法示範與實戰範例

```sql
-- 產生 2024 年全年的月份序列
SELECT generate_series(
    '2024-01-01'::date,
    '2024-12-01'::date,
    '1 month'::interval
)::date AS month;

-- 實際應用：確保每個月都有一列（即使沒有業績也顯示 0）
WITH all_months AS (
    SELECT generate_series(
        '2024-01-01'::date,
        '2024-12-01'::date,
        '1 month'::interval
    )::date AS month
),
actual_revenue AS (
    SELECT
        DATE_TRUNC('month', order_date)::date AS month,
        SUM(total_amount)                      AS revenue
    FROM orders
    WHERE status = 'COMPLETED'
      AND EXTRACT(YEAR FROM order_date) = 2024
    GROUP BY DATE_TRUNC('month', order_date)
)
SELECT
    TO_CHAR(m.month, 'YYYY-MM')      AS 月份,
    COALESCE(r.revenue, 0)           AS 業績
FROM all_months m
LEFT JOIN actual_revenue r ON m.month = r.month
ORDER BY m.month;
```

## 二、字串函數完整指南

> 🎯 **這一節最重要的一件事（心智定位）**：
> 字串函數是資料衛生（Data Hygiene）的第一道防線；透過清理（TRIM/UPPER）、拆分（SPLIT_PART）與聚合（STRING_AGG），將雜亂髒文本規格化為標準實體。
>
> 💼 **為什麼非學不可（避坑痛點）**：
> 現實中客戶填表有空格、有大小寫混雜，若不經清洗直接比對，`'Apex'` 與 `'apex '` 就會被判為兩家不同公司，直接破壞資料庫約束與客戶統計！

### 2.1 清理函數：TRIM / UPPER / LOWER / REPLACE

#### 1. 語法結構與參數說明

在資料清理（Data Cleaning）中，最常面對的是多餘空格、英文大小寫不一、以及混入特殊符號等問題。PostgreSQL 提供了標準清理函式群：

```sql
-- 1. 空白與字符去除
TRIM([LEADING | TRAILING | BOTH] [characters FROM] string)
LTRIM(string [, characters])   -- 只移除左邊 (Leading)
RTRIM(string [, characters])   -- 只移除右邊 (Trailing)

-- 2. 字母大小寫標準化
UPPER(string)    -- 轉為全大寫
LOWER(string)    -- 轉為全小寫
INITCAP(string)  -- 每個單詞首字母大寫（Title Case）

-- 3. 子字串替換
REPLACE(string, from_substring, to_substring)
```

| 函數名稱 | 參數說明 | 回傳值 | 商業應用場景 |
| :--- | :--- | :--- | :--- |
| `TRIM(str)` | 預設移除首尾空白。亦可指定字符，如 `TRIM('$' FROM price)` | `TEXT` | 清理表單文字首尾誤打的空白字元 |
| `LTRIM` / `RTRIM` | 移除左側 / 右側指定字符 | `TEXT` | 移除條碼左側前導零或尾隨符號 |
| `UPPER` / `LOWER` | 轉換英文字母為大寫 / 小寫 | `TEXT` | 避免 `'Apex'` 與 `'apex'` 被判定為不同客戶 |
| `INITCAP(str)` | 將每個英文單詞的首字母轉為大寫，其餘小寫 | `TEXT` | 人名、職稱、城市英文名稱美化排版 |
| `REPLACE(s, f, t)` | 將字串 `s` 中所有出現的 `f` 替換為 `t` | `TEXT` | 移除貨幣逗號、將斜線日期替換為破折號 |

#### 2. 語法示範與實戰範例

```sql
-- 情境：客戶名稱從 CRM 匯入，有大小寫不一致和多餘空格
SELECT
    '  台灣科技有限公司  '                   AS 原始,
    TRIM('  台灣科技有限公司  ')             AS TRIM_去除首尾空白,
    LTRIM('  ABC  ')                        AS LTRIM_只去左邊,
    RTRIM('  ABC  ')                        AS RTRIM_只去右邊,

    UPPER('hello world')                    AS 全大寫,
    LOWER('HELLO WORLD')                    AS 全小寫,
    INITCAP('hello world')                  AS 首字大寫,

    REPLACE('2024/09/15', '/', '-')         AS 取代斜線為破折號,
    REPLACE('NT$1,234,567', ',', '')        AS 移除金額逗號;

-- 實際應用：標準化公司名稱（去空格 + 統一大寫）
UPDATE customers
SET company_name = TRIM(UPPER(company_name))
WHERE company_name != TRIM(UPPER(company_name));
```

### 2.2 擷取函數：SUBSTRING / SPLIT_PART / LEFT / RIGHT / LENGTH

#### 1. 語法結構與參數說明

當結構化資訊被複合打包在單一字串中（如編號 `ORD-2024-001` 或電話 `02-23456789`），必須精準依照「位置」或「特定分隔符」進行拆分。

```sql
-- 1. ANSI SQL 標準位置擷取（推薦）
SUBSTRING(string FROM start_position [FOR length])
-- 或 PostgreSQL 逗號語法：SUBSTRING(string, start_position, length)

-- 2. 邊界快速截取
LEFT(string, n)   -- 擷取最左側 n 個字元
RIGHT(string, n)  -- 擷取最右側 n 個字元

-- 3. 長度測量
LENGTH(string)    -- 計算字串長度（Unicode 字元計數）

-- 4. 分隔符切割（極高頻應用）
SPLIT_PART(string, delimiter, field_number)
```

| 參數 | 型別 | 說明 |
| :--- | :--- | :--- |
| `start_position` | `INTEGER` | 起始截取位置。**核心觀念：SQL 是 1-based**（第一個字元索引為 1，非 0-based！）。 |
| `length` / `n` | `INTEGER` | 欲擷取的字元長度 / 數量。 |
| `delimiter` | `TEXT` | 切割字串的分隔符號（如 `'-'`, `','`, `'/'`）。 |
| `field_number` | `INTEGER` | 欲擷取第幾個欄位（從 1 起算）。若超出分割段數，**回傳空字串 `""`**。 |

#### 2. 語法示範與實戰範例

```sql
-- SUBSTRING：擷取特定位置的字串
SELECT
    'ORD-2024-001'                            AS 原始,
    SUBSTRING('ORD-2024-001' FROM 5 FOR 4)   AS 擷取年份,     -- 2024
    LEFT('ORD-2024-001', 3)                  AS 左邊3碼,      -- ORD
    RIGHT('ORD-2024-001', 3)                 AS 右邊3碼,      -- 001
    LENGTH('ORD-2024-001')                   AS 字串長度;     -- 12

-- SPLIT_PART：用分隔符切割字串（像 Excel 的文字到欄）
SELECT
    'SRV-001-PRO'                            AS 產品代號,
    SPLIT_PART('SRV-001-PRO', '-', 1)       AS 第1段,        -- SRV
    SPLIT_PART('SRV-001-PRO', '-', 2)       AS 第2段,        -- 001
    SPLIT_PART('SRV-001-PRO', '-', 3)       AS 第3段;        -- PRO

-- 範例 A（純字串測試）：從標準三段式單號 ORD-2024-001 拆出年份與序號
SELECT
    'ORD-2024-001'                          AS 示範單號,
    SPLIT_PART('ORD-2024-001', '-', 2)::int AS 訂單年份,    -- 2024 (int)
    SPLIT_PART('ORD-2024-001', '-', 3)::int AS 訂單序號;    -- 1 (int)

-- 範例 B（實體資料庫查詢）：對應當前 orders 表真實格式（ORD-000001 兩段式流水號）
SELECT
    order_number,
    SPLIT_PART(order_number, '-', 1)      AS 前綴,        -- ORD
    SPLIT_PART(order_number, '-', 2)::int AS 訂單序號      -- 1, 2, 3...
FROM orders
LIMIT 10;
```

> ⚠️ **注意：`SPLIT_PART` 轉型陷阱**
> 
> `SPLIT_PART` 若切不出第 N 段，回傳的是**空字串 `""`** 而不是 `NULL`，直接 `::int` 轉型會報錯。生產環境應使用以下防禦性寫法：
> 
> ```sql
> -- 防禦寫法 1：先用正規表示式篩選合規格式再拆分轉型
> SELECT
>     order_number,
>     SPLIT_PART(order_number, '-', 2)::int AS 訂單年份,
>     SPLIT_PART(order_number, '-', 3)::int AS 訂單序號
> FROM orders
> WHERE order_number ~ '^ORD-\d{4}-\d+$'
> LIMIT 10;
> 
> -- 防禦寫法 2：CASE 條件式安全轉型（非純數字退回 NULL）
> SELECT
>     order_number,
>     CASE
>         WHEN SPLIT_PART(order_number, '-', 2) ~ '^\d+$'
>         THEN SPLIT_PART(order_number, '-', 2)::int
>     END AS 訂單年份,
>     CASE
>         WHEN SPLIT_PART(order_number, '-', 3) ~ '^\d+$'
>         THEN SPLIT_PART(order_number, '-', 3)::int
>     END AS 訂單序號
> FROM orders
> LIMIT 10;
> ```

### 2.3 組合函數：CONCAT / || / STRING_AGG

#### 1. 語法結構與參數說明

將多個欄位或多列文字合併為單一字串，常用於產生全名、複合編號或一對多關聯清單。

```sql
-- 1. 串接函數（NULL 安全）
CONCAT(val1, val2, ...)

-- 2. 串接運算子（遵循 SQL 三值邏輯）
val1 || val2 || ...

-- 3. 分組聚合字串（類似 MySQL 的 GROUP_CONCAT 或 Excel 的 TEXTJOIN）
STRING_AGG(expression, delimiter [ORDER BY sort_column [ASC | DESC]])
```

#### 2. 💡 重要對比：`CONCAT` vs `||`（面對 NULL 的行為差天共地！）

這是 SQL 面試與實務生產中最容易踩坑的細節：

| 方式 | 遇到 NULL 的處理邏輯 | 範例 | 結果 | 應用場景 |
| :--- | :--- | :--- | :--- | :--- |
| `CONCAT(a, b)` | **自動忽略 NULL**（視為空字串） | `CONCAT('區域: ', NULL, '台北')` | `'區域: 台北'` | 欄位容許為空，仍需拼出完整標籤時 |
| `a \|\| b` | **遵循三值邏輯**（任一為 NULL 即為 NULL） | `'區域: ' \|\| NULL \|\| '台北'` | `NULL` | 強制要求資料不可缺漏，否則無效時 |

> 📌 **STRING_AGG 聚合機制**：`STRING_AGG` 是 Aggregate 函數，必須搭配 `GROUP BY` 使用。它能將屬於同一組別的多列文字，依指定排序以逗號或分號串接成單一字串。

#### 3. 語法示範與實戰範例

```sql
-- 字串合併
SELECT
    CONCAT(s.name, ' (', s.region, ')')      AS 業務_含區域,
    s.name || ' - ' || s.email               AS 業務_含信箱
FROM salespeople s;

-- STRING_AGG：將多列合併為一個字串（類似 GROUP_CONCAT）
-- 情境：列出每個客戶曾購買的所有產品類別
SELECT
    c.company_name,
    STRING_AGG(
        DISTINCT p.category,
        ', ' ORDER BY p.category
    ) AS 購買過的類別
FROM customers c
JOIN orders o     ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p   ON oi.product_id = p.product_id
WHERE o.status = 'COMPLETED'
GROUP BY c.customer_id, c.company_name
ORDER BY c.company_name;
```

### 2.4 搜尋函數：LIKE / ILIKE / POSITION

#### 1. 語法結構與參數說明

```sql
-- 模糊模式搜尋
string LIKE pattern           -- 區分大小寫
string ILIKE pattern          -- 不區分大小寫（PostgreSQL 特色語法）

-- 位置搜尋
POSITION(substring IN string) -- 尋找子字串在母字串中第一次出現的索引位置
```

| 元素 | 說明 | 範例與意義 |
| :--- | :--- | :--- |
| `%` (百分比) | 比對 **0 個、1 個或多個**任意字元 | `'ORD%'`（以 ORD 開頭的所有文字） |
| `_` (底線) | 剛好比對 **1 個**任意字元 | `'ORD-____-___'`（嚴格匹配固定位數） |
| `ILIKE` | 忽略大小寫搜尋（Case-Insensitive LIKE） | `'apple' ILIKE 'A%'` → `TRUE` |
| `POSITION(sub IN s)` | 回傳子字串起始位置（**1-based**）。**若找不到則回傳 `0`** | `POSITION('科技' IN '台灣科技')` → `3` |

#### 2. 語法示範與實戰範例

```sql
-- LIKE：大小寫敏感的模糊搜尋
-- ILIKE：大小寫不敏感（PostgreSQL 特有）
SELECT company_name
FROM customers
WHERE company_name ILIKE '%科技%'        -- 包含「科技」（不分大小寫）
   OR company_name ILIKE 'taiwan%'       -- 以 taiwan 開頭（不分大小寫）
   OR company_name LIKE '%有限公司';     -- 以「有限公司」結尾

-- POSITION：找到子字串的位置（找不到回傳 0）
SELECT
    company_name,
    POSITION('科技' IN company_name) AS 科技二字的位置
FROM customers
WHERE POSITION('科技' IN company_name) > 0;
```

### 2.5 正規表示式：REGEXP_REPLACE / REGEXP_MATCHES / 正則運算子

#### 1. 語法結構與參數說明

當標準的 `LIKE` 無法滿足複雜文字特徵（如檢核統一編號 8 碼純數字、提取特定英文代碼、替換所有非數字字元）時，正規表示式是資料衛生工程的終極武器。

```sql
-- 1. 正則匹配運算子（用於 WHERE 條件篩選）
string ~ pattern        -- 匹配（區分大小寫）
string ~* pattern       -- 匹配（不區分大小寫）
string !~ pattern       -- 不匹配（區分大小寫）
string !~* pattern      -- 不匹配（不區分大小寫）

-- 2. 正則替換函數
REGEXP_REPLACE(string, pattern, replacement [, flags])

-- 3. 正則擷取函數
REGEXP_MATCHES(string, pattern [, flags])
```

| 參數 / 標記 | 說明 |
| :--- | :--- |
| `pattern` | 正規表示式字串（如 `'^\d{8}$'` 代表剛好 8 位純數字）。 |
| `replacement` | 替換的目標文字。 |
| `flags` | 修飾旗標。最常用為 `'g'`（Global，全域替換）。**注意：預設若無 `'g'`，只會替換第 1 個符合的地方！** |
| `REGEXP_MATCHES` | 回傳型別為 `text[]`（文字陣列）。若要取得提取結果，需加上陣列索引 `(REGEXP_MATCHES(...))[1]`。 |

#### 2. 語法示範與實戰範例

```sql
-- 正規表示式取代
SELECT
    -- 移除所有非數字字元（適合清理電話號碼）
    REGEXP_REPLACE('(02) 2345-6789', '[^0-9]', '', 'g') AS 純數字電話,

    -- 移除開頭的數字
    REGEXP_REPLACE('123ABC', '^\d+', '')                AS 去掉開頭數字,

    -- 標準化統一編號格式（確保 8 位數）
    REGEXP_REPLACE('  12345678  ', '\s', '', 'g')       AS 去掉空格;

-- 正規表示式篩選（~ 運算子）
SELECT company_name, tax_id
FROM customers
WHERE tax_id ~ '^\d{8}$'    -- 統一編號必須是 8 位純數字
  AND tax_id IS NOT NULL;

-- REGEXP_MATCHES：擷取符合條件的子字串
SELECT
    product_code,
    (REGEXP_MATCHES(product_code, '[A-Z]+'))[1]   AS 類別代碼,  -- SRV, HW, SW...
    (REGEXP_MATCHES(product_code, '\d+'))[1]       AS 產品序號
FROM products;
```

### 2.6 字串函數組合應用：資料清理實戰

**情境**：從 Excel 匯入的客戶資料有各種格式問題，需要一次性清理：

```sql
-- 建立清理後的 staging 表
SELECT
    customer_id,
    -- 公司名稱：去空格、移除多餘特殊符號
    TRIM(REGEXP_REPLACE(company_name, '\s+', ' ', 'g'))
                                                    AS clean_company_name,

    -- 統一編號：移除所有非數字、確保 8 位
    CASE
        WHEN LENGTH(REGEXP_REPLACE(tax_id, '[^0-9]', '', 'g')) = 8
        THEN REGEXP_REPLACE(tax_id, '[^0-9]', '', 'g')
        ELSE NULL  -- 格式錯誤的標記為 NULL，等待人工確認
    END                                             AS clean_tax_id,

    -- 產業別：統一為大寫
    UPPER(TRIM(industry))                           AS clean_industry,

    -- 城市：移除郵遞區號（如 "100 台北市" → "台北市"）
    TRIM(REGEXP_REPLACE(city, '^\d{3,6}\s*', ''))  AS clean_city,

    -- 標記是否需要人工複查
    CASE
        WHEN tax_id IS NULL OR LENGTH(REGEXP_REPLACE(tax_id, '[^0-9]', '', 'g')) != 8
        THEN TRUE
        ELSE FALSE
    END                                             AS needs_review
FROM staging_customers;
```

> 💡 **字串函數核心收斂**：
> **TRIM 去空格、UPPER 統規格；SPLIT_PART 拆欄位，STRING_AGG 拼清單。**

## 三、效能優化入門：讀懂 EXPLAIN

> 🎯 **這一節最重要的一件事（心智定位）**：
> EXPLAIN ANALYZE 是資料庫查詢的「斷層掃描器」，Seq Scan 代表地毯式全表硬翻，Index Scan 才是精準的字典索驥。
>
> 💼 **為什麼非學不可（避坑痛點）**：
> 在測試機上只有 1,000 筆資料，差勁的 SQL 只要 5ms 就能跑完；上線後百萬級訂單一灌進來，全表掃描直接吃滿 CPU 造成資料庫伺服器瞬間斷線！

### 3.1 為什麼要關心效能？

同一個查詢需求，寫法不同，效能可能差 **100 倍以上**。在生產環境的報表系統或儀表板中，一個慢查詢會讓所有使用者都在等待。

---

### 3.2 EXPLAIN vs EXPLAIN ANALYZE

#### 1. 語法結構與關鍵選項說明

PostgreSQL 的 `EXPLAIN` 指令讓開發者能窺探查詢最佳化器（Query Planner）的決策內幕：

```sql
EXPLAIN [ ( option [, ...] ) ] statement
```

| 選項參數 | 預設值 | 作用與說明 |
| :--- | :--- | :--- |
| `ANALYZE` | `FALSE` | **真正執行查詢**並顯示實際花費時間與實際回傳列數。（⚠️ 警告：若對 `UPDATE`/`DELETE` 使用會真正修改資料，請在交易 `ROLLBACK` 中執行！） |
| `BUFFERS` | `FALSE` | 顯示記憶體快取命中（Shared Hit）與磁碟讀取區塊數（必須搭配 `ANALYZE` 使用）。 |
| `COSTS` | `TRUE` | 顯示計畫器預估的啟動成本與總成本（`cost=啟動成本..總成本`）。 |
| `TIMING` | `TRUE` | 顯示每個執行節點實際花費的毫秒數（搭配 `ANALYZE`）。 |
| `FORMAT` | `TEXT` | 輸出格式，可選 `TEXT`, `JSON`, `XML`, `YAML`。 |

#### 2. 語法示範與用法

```sql
-- EXPLAIN：只顯示「計畫」，不真正執行
-- 用途：安全地預覽查詢計畫，不會改動資料
EXPLAIN
SELECT * FROM orders WHERE customer_id = 42;

-- EXPLAIN ANALYZE：真正執行並顯示「實際執行時間」
-- 用途：測量實際效能，找出瓶頸
EXPLAIN ANALYZE
SELECT * FROM orders WHERE customer_id = 42;

-- 加上 BUFFERS：顯示記憶體緩衝區使用情況
EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT)
SELECT
    c.company_name,
    SUM(o.total_amount)
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
WHERE o.status = 'COMPLETED'
GROUP BY c.company_name;
```

### 3.3 讀懂 EXPLAIN 輸出

```
EXPLAIN 輸出範例：
-----------------------------------------------------------------------------------
Hash Join  (cost=125.42..3258.19 rows=5234 width=64)
             (actual time=12.345..89.123 rows=5190 loops=1)
  Hash Cond: (o.customer_id = c.customer_id)
  ->  Seq Scan on orders o                         ← 全表掃描！（可能的瓶頸）
        (cost=0.00..2800.00 rows=75000 width=32)
        Filter: (status = 'COMPLETED')
        Rows Removed by Filter: 12300              ← 過濾掉 12300 列
  ->  Hash  (cost=98.00..98.00 rows=2194 width=32)
        ->  Seq Scan on customers c
              (cost=0.00..98.00 rows=2194 width=32)
Planning Time: 1.234 ms
Execution Time: 89.456 ms                          ← 重點：實際執行時間
```

**關鍵指標解讀**：

| 指標 | 說明 | 警示信號 |
| --------------------- | ------------------ | -------------------------------------------- |
| `Seq Scan` | 全表掃描，逐列讀取 | 大表上的 Seq Scan → 考慮加 Index |
| `Index Scan` | 使用索引 | 一般情況下的良好信號 |
| `Bitmap Index Scan` | 批次使用索引 | 中等效能 |
| `Hash Join` | 雜湊連結 | 適合大表 JOIN |
| `Nested Loop` | 巢狀迴圈 | 小表 JOIN 效率佳，大表慢 |
| `actual time=X..Y` | 開始到結束的毫秒數 | Y > 1000ms 需要優化 |
| `rows=N` | 實際回傳的列數 | 若 estimate 和 actual 差太多 → 需要 ANALYZE |

### 3.4 常見慢查詢原因與修正

#### 核心原理：SARGable（Search Argument Able）原則

> 📌 **什麼是 SARGable？**
> 「SARGable」代表查詢條件**能夠直接利用索引的 B-Tree 結構進行快速範圍查找或等值二分搜尋**。
> 一旦你在 `WHERE` 條件中對「索引欄位本體」套上了函數或運算子（如 `WHERE EXTRACT(YEAR FROM order_date) = 2024` 或 `WHERE price * 1.05 > 100`），資料庫就無法直接透過索引值跳轉，被迫將全表所有資料逐一運算後比對，造成**索引失效、退化為全表掃描（Seq Scan）**！

#### 原因 1：在 WHERE 子句中對欄位做運算（破壞 SARGable，使 Index 失效）

```sql
-- ❌ 慢：對 order_date 做函數運算，無法使用 Index
WHERE EXTRACT(YEAR FROM order_date) = 2024

-- ✅ 快：改為範圍條件，可使用 Index
WHERE order_date >= '2024-01-01' AND order_date < '2025-01-01'

-- ❌ 慢：對 total_amount 做運算
WHERE total_amount * 1.05 > 100000

-- ✅ 快：把計算移到右邊
WHERE total_amount > 100000 / 1.05
```

#### 原因 2：SELECT * 取回不需要的欄位

```sql
-- ❌ 慢：取回所有欄位（包含可能的 TEXT/BLOB 欄位）
SELECT * FROM orders WHERE customer_id = 42;

-- ✅ 快：只取需要的欄位
SELECT order_id, order_number, order_date, total_amount
FROM orders
WHERE customer_id = 42;
```

#### 原因 3：JOIN 順序不佳

```sql
-- ❌ 可能較慢：先 JOIN 大表，再過濾
SELECT * FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
WHERE c.city = '台北市';

-- ✅ 較快：先過濾小表，再 JOIN（PostgreSQL 最佳化器通常會自動處理，但明確寫出更好）
WITH taipei_customers AS (
    SELECT customer_id FROM customers WHERE city = '台北市'
)
SELECT o.*
FROM orders o
JOIN taipei_customers tc ON o.customer_id = tc.customer_id;
```

### 3.5 Index 設計原則

#### 1. 什麼是 Index？

Index 就像書本的目錄，讓資料庫不用從第一頁掃到最後一頁，直接跳到對的位置。代價是：**寫入變慢（INSERT/UPDATE 時需同步維護索引樹結構）、佔用額外儲存空間**。

#### 2. 建立 Index 的完整語法結構

```sql
CREATE [UNIQUE] INDEX [CONCURRENTLY] index_name
ON table_name [USING { btree | hash | gist | gin }] (
    column_name [ASC | DESC] [, ...]
)
[WHERE predicate];  -- 部分索引（Partial Index）過濾條件
```

| 關鍵字 / 參數 | 說明 | 實戰情境 |
| :--- | :--- | :--- |
| `btree` (預設) | 最通用的平衡二元樹索引，支援 `=`, `<`, `>`, `BETWEEN`, `IN` | 數值、字串、日期範圍查找 |
| `UNIQUE` | 唯一索引，加速查詢的同時強制禁止重複值 | 統一編號、電子信箱、業務唯一號 |
| `CONCURRENTLY` | **生產環境熱建索引必備**！建立時不鎖定整張表，線上業務可照常讀寫 | 幾百萬筆資料的正式環境補建索引 |
| `複合 Index (A, B)` | 同時索引多個欄位。遵守**最左前綴原則（Leftmost Prefix Rule）** | 常用於 `WHERE status = ... ORDER BY order_date` |
| `部分 Index (WHERE ...)` | 只針對符合條件的資料行建立索引，體積極小且維護成本極低 | 只對有效訂單 `WHERE status = 'COMPLETED'` 建索引 |

#### 3. 實戰語法示範

```sql
-- 基本單欄 Index
CREATE INDEX idx_orders_customer_id ON orders(customer_id);

-- 複合 Index（欄位順序很重要！常作為等值查詢的欄位放前面）
CREATE INDEX idx_orders_status_date ON orders(status, order_date);

-- 部分 Index（只對滿足條件的列建立索引，更省空間）
CREATE INDEX idx_orders_completed_date
ON orders(order_date)
WHERE status = 'COMPLETED';

-- 唯一 Index（同時強制唯一性）
CREATE UNIQUE INDEX idx_customers_tax_id
ON customers(tax_id)
WHERE tax_id IS NOT NULL;

-- 查看表上有哪些 Index
SELECT indexname, indexdef
FROM pg_indexes
WHERE tablename = 'orders';
```

### 3.6 Index 設計決策樹

```
需不需要建 Index？

這個欄位有多少「獨特值」（Cardinality）？
  ├── 很少（如：status 只有 3 種值）→ Cardinality 低 → Index 效果差，考慮「部分 Index」
  └── 很多（如：customer_id、order_number）→ Cardinality 高 → 強烈建議建 Index

這個欄位在 WHERE / JOIN ON / ORDER BY 中頻繁出現嗎？
  ├── 是 → 建議建 Index
  └── 否 → 暫時不建

這張表的讀寫比例？
  ├── 讀多寫少（報表查詢）→ Index 越多越好
  └── 寫多讀少（交易系統）→ Index 謹慎添加，每個 Index 都會拖慢 INSERT/UPDATE
```

**常見的 Index 應用場景**：

```sql
-- orders 表的常用 Index 設計
CREATE INDEX idx_orders_customer_id  ON orders(customer_id);       -- JOIN
CREATE INDEX idx_orders_salesperson  ON orders(salesperson_id);    -- JOIN
CREATE INDEX idx_orders_status_date  ON orders(status, order_date); -- WHERE + ORDER BY
CREATE INDEX idx_orders_date         ON orders(order_date);        -- 時間範圍查詢

-- customers 表
CREATE INDEX idx_customers_industry  ON customers(industry);
CREATE INDEX idx_customers_city      ON customers(city);
CREATE UNIQUE INDEX idx_customers_tax ON customers(tax_id) WHERE tax_id IS NOT NULL;
```

### 3.7 ANALYZE — 更新統計資訊

PostgreSQL 的查詢計畫器依賴**統計資訊**來估算每個查詢的成本。若資料大量更新後沒有重新統計，計畫器可能做出錯誤判斷：

```sql
-- 對單一表格更新統計資訊
ANALYZE orders;

-- 對整個資料庫更新統計資訊（通常由 autovacuum 自動處理）
ANALYZE;

-- VACUUM ANALYZE：同時清理死列和更新統計
VACUUM ANALYZE orders;
```

> 💡 **效能優化核心收斂**：
> **WHERE 欄位忌包函數，破壞索引變全表；高基數欄位建 Index，ANALYZE 定期新統計。**

### 題目 1：最近 30 天 vs 上個月 30 天的業績比較

**需求**：財務主管想快速比較最近 30 天和前 30 天的業績，並計算環比變化。

<details>
<summary>💡 需要思考提示嗎？（點擊展開提示）</summary>

1. 使用兩段 CTE：`recent` 與 `previous`。
2. 利用 `CURRENT_DATE - INTERVAL '30 days'` 與 `CURRENT_DATE - INTERVAL '60 days'` 界定動態區間。
3. 主查詢進行純量交叉相減並計算百分比：`(recent - previous) / previous * 100`。

</details>

<details>
<summary>✅ 寫完了？點擊查看參考解答與詳解</summary>

```sql
WITH recent AS (
    SELECT SUM(total_amount) AS revenue
    FROM orders
    WHERE status = 'COMPLETED'
      AND order_date >= CURRENT_DATE - INTERVAL '30 days'
),
previous AS (
    SELECT SUM(total_amount) AS revenue
    FROM orders
    WHERE status = 'COMPLETED'
      AND order_date >= CURRENT_DATE - INTERVAL '60 days'
      AND order_date <  CURRENT_DATE - INTERVAL '30 days'
)
SELECT
    r.revenue                               AS 近30天業績,
    p.revenue                               AS 前30天業績,
    ROUND(r.revenue - p.revenue, 0)         AS 差額,
    ROUND((r.revenue - p.revenue) / p.revenue * 100, 1) AS 環比成長率
FROM recent r, previous p;
```

</details>

### 題目 2：找出訂單號碼格式異常的資料

**需求**：訂單號碼應為 `ORD-YYYY-NNN` 格式（如 ORD-2024-001），找出不符合此格式的異常訂單。

<details>
<summary>💡 需要思考提示嗎？（點擊展開提示）</summary>

1. 使用 PostgreSQL 正規表示式運算子 `!~`（不匹配）。
2. 標準模式為 `^ORD-\d{4}-\d{3,}$`。

</details>

<details>
<summary>✅ 寫完了？點擊查看參考解答與詳解</summary>

```sql
SELECT
    order_id,
    order_number,
    '格式應為 ORD-YYYY-NNN' AS 問題描述
FROM orders
WHERE order_number !~ '^ORD-\d{4}-\d{3,}$'   -- 正規表示式：不符合標準格式
ORDER BY order_id;
```

</details>

### 題目 3：各月份業績報表（含月份名稱、季度標籤）

**需求**：輸出包含中文月份名稱、季度標籤的業績摘要表。

<details>
<summary>💡 需要思考提示嗎？（點擊展開提示）</summary>

1. 中文月份名稱使用 `TO_CHAR(DATE_TRUNC('month', order_date), 'YYYY年MM月')`。
2. 季度標籤使用 `'Q' || EXTRACT(QUARTER FROM order_date)::text`。
3. 按截斷月份與季度分組加總。

</details>

<details>
<summary>✅ 寫完了？點擊查看參考解答與詳解</summary>

```sql
SELECT
    TO_CHAR(DATE_TRUNC('month', order_date), 'YYYY年MM月')   AS 月份,
    'Q' || EXTRACT(QUARTER FROM order_date)::text             AS 季度,
    COUNT(DISTINCT order_id)                                  AS 訂單數,
    SUM(total_amount)                                         AS 業績,
    ROUND(AVG(total_amount), 0)                               AS 平均訂單金額,
    MAX(total_amount)                                         AS 最大單筆金額
FROM orders
WHERE status = 'COMPLETED'
GROUP BY DATE_TRUNC('month', order_date), EXTRACT(QUARTER FROM order_date)
ORDER BY DATE_TRUNC('month', order_date);
```

</details>

### 題目 4：客戶合作年資分析

**需求**：根據客戶建立日期，計算合作年資，並分類為「新客戶/成長客戶/成熟客戶/老客戶」。

<details>
<summary>💡 需要思考提示嗎？（點擊展開提示）</summary>

1. 使用 `AGE(CURRENT_DATE, created_at::date)` 取得精確年齡區間。
2. 透過 `EXTRACT(YEAR FROM AGE(...))` 取出整數年數。
3. 用 `CASE WHEN` 依年資長短賦予階梯標籤。

</details>

<details>
<summary>✅ 寫完了？點擊查看參考解答與詳解</summary>

```sql
SELECT
    company_name,
    created_at::date                                            AS 合作開始日,
    EXTRACT(YEAR FROM AGE(CURRENT_DATE, created_at::date))::int AS 合作年數,
    AGE(CURRENT_DATE, created_at::date)                         AS 合作時長,
    CASE
        WHEN EXTRACT(YEAR FROM AGE(CURRENT_DATE, created_at::date)) < 1
        THEN '🌱 新客戶 (<1年)'
        WHEN EXTRACT(YEAR FROM AGE(CURRENT_DATE, created_at::date)) < 3
        THEN '📈 成長客戶 (1-3年)'
        WHEN EXTRACT(YEAR FROM AGE(CURRENT_DATE, created_at::date)) < 5
        THEN '💼 成熟客戶 (3-5年)'
        ELSE '🏆 老客戶 (5年以上)'
    END                                                         AS 客戶成熟度
FROM customers
WHERE status = 'ACTIVE'
ORDER BY created_at;
```

</details>

### 題目 5：STRING_AGG 生成客戶購買清單報表

**需求**：產生一份「客戶 × 購買過的產品」報表，每位客戶一列，購買的產品名稱以逗號分隔。

<details>
<summary>💡 需要思考提示嗎？（點擊展開提示）</summary>

1. 跨表關聯 `customers` ➜ `orders` ➜ `order_items` ➜ `products`。
2. 使用 `STRING_AGG(DISTINCT p.product_name, ', ' ORDER BY p.product_name)` 將商品名稱串成單一字串。
3. 依客戶 ID 與名稱分組。

</details>

<details>
<summary>✅ 寫完了？點擊查看參考解答與詳解</summary>

```sql
SELECT
    c.company_name                                              AS 客戶名稱,
    c.industry                                                  AS 產業,
    COUNT(DISTINCT o.order_id)                                  AS 訂單總數,
    SUM(o.total_amount)                                         AS 總購買金額,
    COUNT(DISTINCT p.product_id)                                AS 購買品項數,
    STRING_AGG(DISTINCT p.product_name, ', ' ORDER BY p.product_name)
                                                                AS 購買過的產品
FROM customers c
JOIN orders o     ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p   ON oi.product_id = p.product_id
WHERE o.status = 'COMPLETED'
  AND c.status = 'ACTIVE'
GROUP BY c.customer_id, c.company_name, c.industry
ORDER BY 總購買金額 DESC;
```

</details>

> 💡 **日期、字串與效能核心收斂**：
> **日期截斷算趨勢，字串拆合清髒污；索引防護看 EXPLAIN，高頻慢查無遁形。**

## 五、本章重點彙整

```
日期函數
  EXTRACT(part FROM date)     → 擷取年/月/日/季/週
  DATE_TRUNC('month', date)   → 截斷到月初（GROUP BY 月份必備）
  TO_CHAR(date, 'format')     → 格式化輸出（報表顯示）
  TO_DATE(str, 'format')      → 字串解析為日期（資料匯入）
  AGE(date1, date2)           → 計算時間差（年月日形式）
  generate_series(start, end, interval) → 生成連續日期序列

字串函數
  TRIM / LTRIM / RTRIM        → 去空格
  UPPER / LOWER / INITCAP     → 大小寫轉換
  REPLACE(str, from, to)      → 字串取代
  SPLIT_PART(str, delim, n)   → 用分隔符切割
  CONCAT / ||                 → 字串合併
  STRING_AGG(col, sep ORDER BY ...) → 多列合併為一字串
  REGEXP_REPLACE(str, pattern, replacement, flags) → 正規表示式取代

效能優化
  EXPLAIN ANALYZE             → 查看實際執行計畫與時間
  Seq Scan = 全表掃描         → 大表上出現需考慮 Index
  WHERE 子句不要對欄位做計算  → 會破壞 Index
  CREATE INDEX                → 針對 WHERE/JOIN/ORDER BY 欄位
  部分 Index WHERE status='X' → 只對特定值建立索引，更省空間
  ANALYZE                     → 更新統計資訊，讓計畫器做對決定
```
