# A1｜AI 協作工作流 SOP：如何與 AI 一起做出可靠工程成果

> 這不是「AI 幫我寫程式」的筆記，而是「**我如何主導、AI 如何輔助**，共同產出可靠工程成果」的標準作業流程。

## 核心原則

```
你負責：問題定義 / 方案設計 / Review / Test / Debug / 負責
AI 負責：生成 / 比較 / 解釋 / 找問題

不能讓 AI 負責的事情：
- 決定這個系統要解決什麼問題
- 判斷 SQL 的結果是否符合商業邏輯
- 決定 Schema 設計是否正確
- 對系統行為負責
```

---

## 標準工作流（每個任務都用這個流程）

```
Step 1: 問題定義（自己）
  → 我要解決什麼問題？
  → 輸入是什麼？輸出是什麼？
  → 有哪些邊界情況？

Step 2: 方案設計（自己）
  → 我打算怎麼做？
  → 資料流是什麼？
  → 哪些部分我不確定？

Step 3: 自己先寫（重要！）
  → 先寫出自己的版本，哪怕不完整
  → 這是學習的核心，不能跳過

Step 4: AI 協助改進
  → 把自己的版本給 AI
  → 請 AI 指出問題，而不是直接重寫
  → 比較差異，理解為什麼

Step 5: 整合與修改（自己）
  → 不是複製 AI 版本
  → 用自己理解後的方式重寫

Step 6: Test（自己）
  → 邊界情況測試
  → 錯誤輸入測試
  → 結果是否符合預期

Step 7: AI Review（AI）
  → 請 AI 找還有沒有問題
  → 效能問題、安全問題、可讀性問題

Step 8: Commit（自己）
  → 寫有意義的 commit message
  → 紀錄做了什麼決定
```

## SQL 協作 SOP

```
情境：需要寫一條分析 SQL

1. 自己先想邏輯：需要哪些表？JOIN 條件是什麼？GROUP BY 什麼？
2. 自己寫出草稿 SQL
3. 執行，看結果對不對（對照商業邏輯）
4. 給 AI：「我寫了這條 SQL，你覺得哪裡有問題或可以改進？」
5. 理解 AI 的建議，判斷是否採用
6. 最終版本自己敲一遍，不要複製貼上
```

**SQL Debug 提示詞範本：**
```
這條 SQL 跑出來的結果好像不對：
[貼你的 SQL]
[貼結果]
我預期應該是 [預期結果]
你能幫我找出哪裡的邏輯有問題嗎？
```

## Python 協作 SOP

```
情境：需要寫一個函數 / 模組

1. 寫出 Function 簽名 + Type Hint + Docstring
   def clean_company_name(name: str) -> str:
       """
       標準化公司名稱：去除空白、轉小寫、去除常見後綴
       Input: "Apple Inc.  " -> Output: "apple"
       """

2. 寫出測試案例（先寫測試！）
   assert clean_company_name("Apple Inc.  ") == "apple"
   assert clean_company_name("") raises ValueError

3. 自己先實作

4. 給 AI Review：「這個函數還有什麼邊界情況沒處理？」

5. 修改，再跑測試
```

## 常用提示詞範本

### Code Review
```
幫我 Review 這段 Python code，請指出：
1. 有沒有潛在的 Bug
2. 有沒有效能問題
3. 可讀性可以怎麼改善
4. 有沒有沒處理的 Edge Case

[貼你的 code]
```

### Schema Review
```
這是我設計的 B2B 資料庫 Schema：
[貼 DDL 或 ER 描述]

請幫我找出：
1. 有沒有 Normalization 問題
2. 有沒有缺少的 Constraint
3. 有沒有效能考量（Index）
4. 如果業務需求擴展，哪裡會變成瓶頸
```

### SQL Debug
```
這條 SQL 的結果不符合預期：
SQL: [貼 SQL]
結果: [貼結果]
預期: [說明預期]
資料表結構: [簡述]

請幫我找出邏輯問題。
```

### ETL 設計
```
我要設計一個 ETL 流程：
輸入：[描述]
輸出：[描述]
資料品質問題：[列出已知問題]
限制：[效能/時間/環境限制]

請幫我設計架構，並指出哪些地方容易出錯。
```

## AI 的限制（你必須自己判斷的事）

- AI 不知道你的資料裡 `customer_id` 是不是真的唯一
- AI 不知道 `deleted_at IS NULL` 在你的系統是不是正確的過濾條件
- AI 不知道你的公司把「客戶流失」定義為什麼
- AI 生成的 SQL 可能語法正確但商業邏輯錯誤
- AI 的架構建議可能不適合你的資料規模

**這些都需要你用 Domain Knowledge 來判斷。這就是你的核心價值。**
