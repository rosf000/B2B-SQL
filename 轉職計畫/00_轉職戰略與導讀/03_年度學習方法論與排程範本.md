# 03 年度學習方法論與排程範本

## 一、每週 15～20 小時高效學習排程法

在職轉職最常失敗的原因是「時間破碎」與「過度疲勞導致放棄」。建議採用固定節奏的學習區塊：

```text
┌─────────────────┬───────────────────┬──────────────────────────────────────────┐
│ 時間區間        │ 投入時間          │ 學習重心 (Focus Area)                     │
├─────────────────┼───────────────────┼──────────────────────────────────────────┤
│ 週一至週四 晚上 │ 每天 2 小時 (共 8h)│ 吸收新觀念、敲打講義範例、做章節小練習   │
├─────────────────┼───────────────────┼──────────────────────────────────────────┤
│ 週五 晚上       │ 1 小時            │ 整理本週學習筆記、回顧錯誤題目           │
├─────────────────┼───────────────────┼──────────────────────────────────────────┤
│ 週六 上午/下午  │ 4~6 小時          │ 大區塊時間專注進行專案實作、寫程式代碼   │
├─────────────────┼───────────────────┼──────────────────────────────────────────┤
│ 週日 下午/晚上  │ 2~3 小時          │ Git Commit / Push 至 GitHub、撰寫 README │
└─────────────────┴───────────────────┴──────────────────────────────────────────┘
```

## 二、刻意練習的「30 分鐘除錯黃金法則」

當遇到報錯（SyntaxError, ConnectionError, SQL 語法錯誤）時：

1. **第 0～5 分鐘：仔細閱讀錯誤訊息 (Read the Error Traceback)**
   - 絕大多數初學者會直接略過錯誤訊息。請找到最後一行的 Error 類型與報錯行號。
2. **第 5～20 分鐘：使用 Print / 日誌 / 逐步查詢定位問題**
   - 在 Python 中印出變數型態 `print(type(x), x)`。
   - 在 SQL 中把複雜的 JOIN 或 WHERE 條件拆解為單一簡單查詢驗證。
3. **第 20～30 分鐘：查閱官方文件或 Google / Stack Overflow**
   - 搜尋關鍵字：`[語言] + [具體錯誤文字] + [函式庫名稱]`。
4. **超過 30 分鐘卡關：才詢問 AI**
   - 請 AI 解釋「為什麼會報這個錯」以及「修復的原理」，**切忌直接一鍵全選貼上程式碼而不看懂**。

## 三、每月「底線成果驗收標準」(Monthly Deliverables)

每個月最後一個週末，必須確認達成該月的交付物：

| 月份 | 最低標準成果驗收 (Minimum Deliverable) |
| :--- | :--- |
| **Month 1** | 能在 15 分鐘內手寫出包含 JOIN + GROUP BY + HAVING 的商業報表查詢。 |
| **Month 2** | 完成 Project 1 銷售分析 SQL 腳本並產出一份 Markdown 商業分析洞察報告。 |
| **Month 3** | 手繪出標準 B2B 5 張表 ER 圖，並寫出能成功執行的 DDL `CREATE TABLE` 腳本。 |
| **Month 4** | 撰寫出至少 2 個能實際解決電腦檔案/Excel 整理問題的 Python 腳本（非空白 demo）。 |
| **Month 5** | 建立 Python 連接 PostgreSQL 的 ETL 腳本，自動讀取 Excel 清理並入庫。 |
| **Month 6** | 使用 Requests 抓取公開 API，透過 Pandas 處理缺漏值後存入 DB。 |
| **Month 7** | GitHub 個人主頁煥然一新，擁有規範的 Commit 紀錄與綠色活動格子。 |
| **Month 8** | 完成 B2B 旗艦專案，具備完整架構圖、測試腳本與高水準 README。 |
| **Month 9** | 啟動 FastAPI 服務，透過 Swagger UI (`/docs`) 成功測試所有 CRUD 端點。 |
| **Month 10** | 一行指令 `docker compose up` 同時拉起 FastAPI + PostgreSQL 容器並正常對話。 |
| **Month 11** | 自然語言問句輸入後，系統能產出精準 SQL 並回應用戶中文商業答案。 |
| **Month 12** | 產出中英文各一頁履歷，投遞至少 20 家公司，並進行每週面試覆盤。 |
