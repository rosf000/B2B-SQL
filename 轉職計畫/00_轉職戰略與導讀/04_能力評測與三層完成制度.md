# 04 能力評測與三層完成制度 (Career Competence Framework)

> **「轉職者最大的焦慮不是『我學得不夠多』，而是『我不知道自己到底能不能去面試』。」**

為了擺脫「看完了課程卻不敢投履歷」的囤積症，本教材全面導入 **三層完成制度 (Three-Tier Mastery)**、**AI 漸進協作規範 (AI Usage Policy)** 與 **技能成長雷達矩陣**。

## 🎯 1. 三層完成制度 (Three-Tier Mastery)

在每個月的學習模組中，不要強求一次把所有細節吞下。根據你的時間與當前進度，明確錨定自己的完成深度：

```
                    ┌───────────────────────────────┐
                    │  🔴 Level 3: Interview Ready  │  → 能解釋 Trade-off、底層原理與 Failure Case
            ┌───────┴───────────────────────────────┴───────┐
            │         🔵 Level 2: Job Ready (核心目標)       │  → 不看教學能獨立完成、通過測試
    ┌───────┴───────────────────────────────────────────────┴───────┐
    │                 🟢 Level 1: Survival (基礎及格線)             │  → 能照著文件跑通流程、程式碼不報錯
    └───────────────────────────────────────────────────────────────┘
```

| 等級 | 定位 | 能力標準 | 適合情境 | 轉職投遞建議 |
|:---|:---|:---|:---|:---|
| 🟢 **Level 1: Survival** | **基礎跑通線** | 能按照教學步驟完成環境建置、執行程式碼、產出正確結果，對核心專有名詞有基本印象。 | 時間緊迫、初次接觸陌生技術概念時。 | 尚未具備獨立接案或面試競爭力。 |
| 🔵 **Level 2: Job Ready** | **標準就業線** | **不看解答**能獨立從零寫出核心邏輯、通過單元測試與 Data Quality 檢核，具備獨立交付工作任務的能力。 | **每位轉職者的必修通關標準**。 | **達到此標準即可啟動 M8+ 求職投遞！** |
| 🔴 **Level 3: Interview Ready** | **面試溢價線** | 能清晰向面試官解釋架構選型、Trade-off（例如為什麼用 CTE 不用 Subquery、Index 的寫入代價）、能處理系統失敗情境（Failure Scenarios）。 | 衝刺中高階 Junior / 爭取更高薪資 Package。 | 面試中的亮眼殺手鐧，讓你脫穎而出。 |

## 🤖 2. AI 漸進協作規範 (AI Usage Policy)

在 AI 時代，「完全不用 AI」是愚鈍，「全靠 AI 生成複製貼上」是自毀前程。請嚴格依循以下 5 級階梯使用 AI：

```
Level 0 (禁止 AI) ──> Level 1 (除錯提示) ──> Level 2 (程式碼審查) ──> Level 3 (受控生成) ──> Level 4 (多智能體協同)
  概念第一次吸收       只問哪裡有 Bug        自己寫完才給 AI 優化    AI寫框架/自己補邏輯      架構驗證與自動化管線
```

- **Level 0 — 禁止 AI (Concept Phase)**：
  - 當你第一次學習某個語法（如 SQL JOIN 原理、Python 迴圈、Docker 網路）時，**嚴禁開啟 AI 生成程式碼**。必須自己一字一句敲入鍵盤，建立神經肌肉記憶。
- **Level 1 — AI Hint (Debugging Phase)**：
  - 卡關超過 20 分鐘時，可以把報錯貼給 AI，但 Prompt 必須要求：*「請不要直接給我正確程式碼，請提示我哪一行的邏輯有問題，並解釋原因。」*
- **Level 2 — AI Review (Optimization Phase)**：
  - 自己獨立寫出 Level 2 可運行的程式碼後，交給 AI 進行 Code Review：*「這段程式碼效能如何？有沒有邊界條件沒防呆？資料量擴大到 100 萬筆時會發生什麼事？」*
- **Level 3 — AI Generation with Human Gate (Production Phase)**：
  - 進入 M5/M8 專案後，允許 AI 生成樣板程式碼（Boilerplate），但必須遵守 **Human-in-the-loop**：`Generate -> Validate -> Test -> Modify`，每一行程式碼你都能在白板上面試時解釋清楚。
- **Level 4 — AI Agent Pipeline (Architect Phase)**：
  - 旗艦專案中的 Text-to-SQL Agent，必須建立 **防禦鏈路（Guardrails）**：
    `User -> Question -> AI SQL -> SQL Validator -> Permission Check -> Query -> Result Validation -> AI Explanation`。

## 🎓 4. 每月 Exit Exam 考核標準 (Pass Criteria)

每個月末均設有 **Exit Exam** 或 **Gate**，格式統一包含：
1. **必考能力檢核清單**（確認知識盲區已掃除）
2. **商業實戰挑戰題**（不看教學獨立解答）
3. **面試口試必考題**（能否口語化向非技術主管或工程主管解釋）
4. **AI 陷阱審查題**（找出 AI 輸出的潛在邏輯錯誤與效能地雷）

> 💡 **晉級規則**：實作題通過率達 **80% 以上** + 口試題能流暢作答，方可進入下一個月。這不是考試，而是你未來的面試演練！

## 🧪 7. 貫穿 M1～M12 的縱向主線：Testing Mindset（工程測試素養）

真正讓優秀工程師與業餘愛好者拉開差距的，是 **Testing Mindset（對程式碼品質與資料正確性的敬畏心）**。本教材將測試貫穿 12 個月：

```
M1 (SQL比對) ➜ M2 (邊界驗證) ➜ M3 (約束測試) ➜ M4 (Python單元測試) ➜ M5 (ETL Pytest) ➜ M6 (API Mock)
                                                                                       │
M12 (作品集驗證) 🠔 M11 (AI安全評測) 🠔 M10 (部署冒煙測試) 🠔 M9 (TestClient測試) 🠔 M8 (整合測試) 🠔 M7 (容器健康檢查)
```

1. **M1 — SQL 語法與資料對帳測試**：使用 `COUNT(*)`、`GROUP BY` 對帳，驗證 JOIN 前後資料筆數與邊界值。
2. **M2 — 查詢結果邏輯驗證**：利用已知極值與反向驗證法，確保 Window Function 與 NTILE 分群不失真。
3. **M3 — 資料庫約束測試 (Constraint Test)**：故意寫入違規資料，驗證 PK、FK、CHECK、UNIQUE 與 NOT NULL 是否成功阻擋髒資料。
4. **M4 — Python 單元測試起步**：學習使用 Python 內建 `assert` 與 `unittest` 驗證字串與數值防呆。
5. **M5 — ETL 管線測試 (Pytest)**：建立 `test_transform.py` 與 `DataQualityChecker`，驗證清洗邏輯與重試機制。
6. **M6 — API 模擬與防禦測試 (API Mocking)**：模擬 404/429/500/Malformed JSON 回應，驗證例外處理邏輯。
7. **M7 — 容器健康檢查測試 (Container Healthcheck)**：使用 Dockerfile `HEALTHCHECK` 與 `docker inspect` 驗證服務存活。
8. **M8 — 系統端到端整合測試 (E2E Integration Test)**：驗證「資料匯入 ➜ 去重 ➜ 資料庫 ➜ 分析報表」全鏈路不斷裂。
9. **M9 — FastAPI 自動化接口測試**：使用 `TestClient` 撰寫自動化測試，覆蓋 200/404/422 等狀態碼。
10. **M10 — 部署冒煙測試 (Smoke Test)**：使用 cURL / Bash 腳本對已部署的容器與雲端端點進行連線與延遲冒煙測試。
11. **M11 — AI 安全評測 (AI Safety & Guardrail Evaluation)**：建立惡意 Prompt 測試集（如「刪除所有客戶」），驗證 SQL Validator 100% 阻絕破壞性指令。
12. **M12 — 作品集程式碼健康度驗證 (Portfolio Validation)**：執行 `flake8` / `black` 程式碼風格掃描，確保 GitHub Repo 達到業界乾淨度標準。
