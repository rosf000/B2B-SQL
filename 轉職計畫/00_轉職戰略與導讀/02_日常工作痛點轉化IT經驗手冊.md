# 02 日常工作痛點轉化 IT 經驗手冊

> **「在職轉職最珍貴的資產，就是你每天在公司處理資料時感受到的痛苦。」**

## 一、資訊去敏化（機密保護原則）

在將工作中的痛點轉化為作品或面試案例時，**絕對不能違反保密協議（NDA）**。請遵循以下去敏化原則：

| 原始資料（禁止洩漏） | 去敏化 / 抽象化為 IT 題目（完全合法且專業） |
| :--- | :--- |
| 公司真實客戶名稱（如：台積電、聯發科） | 抽象為 `Customer_A001` 或虛構企業名稱（如：Apex Global） |
| 實際產品報價與利潤機密 | 轉換為模擬數值（如：單價 $100~$5,000） |
| 真實客戶統編與個人聯絡方式 | 替換為隨機合成資料或 Fake 測試資料 |

---

## 二、工作痛點與 IT 解法對照庫

| 日常工作痛點 (Business Pain Point) | 背後的 IT / 資料結構問題 | 轉化為專案的技術方案 |
| :--- | :--- | :--- |
| **痛點 1：同一個客戶被重複建檔**<br>例如業務手殘輸入「XX科技股份有限公司」與「XX科技」 | 缺乏唯一性約束 (Unique Constraint) 與主鍵設計，缺乏正規化。 | **解法：** 使用 Python 模糊比對演算法 (Fuzzy Matching) 進行客戶去重，並於 DB 建立標準化統編主鍵。 |
| **痛點 2：Excel 檔案超過 20 萬筆卡死崩潰** | Excel 非資料庫，無法有效支援大量併發讀寫與索引加速。 | **解法：** 建立 PostgreSQL 資料庫，建立 B-Tree 索引，以 SQL 優化查詢速度提升 50 倍。 |
| **痛點 3：每週一早上花 3 小時人工貼報表** | 重複性資料清洗與聚合流程未自動化。 | **解法：** 開發 Python + SQLAlchemy 自動化 ETL 腳本，排程每週一清晨自動拉取並寄送報表。 |
| **痛點 4：業務部與財務部的營收數字對不起來** | 跨表關聯定義不一致、缺乏交易一致性 (ACID)、資料遺失。 | **解法：** 設計完整的訂單-明細-收款關聯式資料庫架構與資料驗證機制。 |
| **痛點 5：老闆臨時要查「上季流失的高價值客戶」** | 非技術人員不會寫 SQL，資料團隊處理臨時需求耗時。 | **解法：** 打造 AI Text-to-SQL 自然語言查詢助理，直接讓業務輸入口語提問獲取報表。 |

## 三、工作痛點記錄範本（建立你的專屬觀察日誌）

建議在 Notion 或本機開一個專屬筆記檔案 `my_work_pain_points.md`，每次在公司覺得資料很煩時就記下一筆：

```markdown
### 📝 工作痛點記錄 [日期: YYYY-MM-DD]
- **情境描述**：今天在整理業務部上傳的客戶名單時...
- **業務影響**：耗費 2 小時人工比對，且發現有 15% 資料遺失聯絡人電話。
- **根本原因 (技術角度)**：表單欄位未設定必填驗證 (Validation)，且缺乏後端資料清洗流程。
- **對應 IT 技能**：Month 4 (Python 檔案清洗) + Month 9 (FastAPI Pydantic 資料驗證)。
- **專案轉化點**：可作為 Month 8 專案中的「客戶資料品質檢測模組 (Data Quality Check)」。
```
