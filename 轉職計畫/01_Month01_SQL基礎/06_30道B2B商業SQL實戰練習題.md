### Q1. 查詢所有處於 'ACTIVE' 狀態的客戶名稱、統編與所在城市

- **商業場景**：行銷部門需要向所有現役正常營運的客戶寄發電子報。
- **思考提示**：查詢 `customers` 表，使用 `WHERE` 等值過濾。
- **預期產出**：共 **8 筆** 資料（排除停權與非現役客戶）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT company_name, tax_id, city 
FROM customers 
WHERE status = 'ACTIVE';
```

- **核心解說**：最經典的單表過濾。文字值請以單引號包裹 `'ACTIVE'`。

</details>

### Q2. 查詢信用額度在 40 萬到 80 萬之間（包含邊界）的所有客戶，並依額度由高到低排序

- **商業場景**：風控部需要盤點中高信用額度的客戶名冊。
- **思考提示**：利用 `BETWEEN ... AND ...` 範圍查詢，搭配 `ORDER BY ... DESC`。
- **預期產出**：共 **6 筆** 資料（額度由 800,000 至 400,000 排序）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT company_name, credit_limit 
FROM customers 
WHERE credit_limit BETWEEN 400000 AND 800000
ORDER BY credit_limit DESC;
```

- **核心解說**：`BETWEEN A AND B` 包含端點值 A 與 B；降冪排序請使用 `DESC`。

</details>

### Q3. 找出所有沒有填寫統一編號 (tax_id) 或處於 'SUSPENDED' 狀態的客戶

- **商業場景**：財務法遵部需找出資料不齊全或已被暫停交易的警示客戶。
- **思考提示**：注意 NULL 的判斷必須用 `IS NULL`，且兩條件為「或」關係 (`OR`)。
- **預期產出**：共 **1 筆** 資料（Jovial Media Group）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT company_name, tax_id, status 
FROM customers 
WHERE tax_id IS NULL OR status = 'SUSPENDED';
```

- **核心解說**：絕不可寫成 `tax_id = NULL`，在 SQL 中任何值與 NULL 比較皆為未知。

</details>

### Q6. 查詢所有 2024 年第一季（2024-01-01 至 2024-03-31）成立且狀態為 'COMPLETED' 的訂單

- **商業場景**：季末財務會計需要結算 Q1 已完成的合格交易訂單。
- **思考提示**：查詢 `orders` 表，使用日期區間 `BETWEEN` 加上狀態篩選，並依下單日期由舊到新排序。
- **預期產出**：共 **6 筆完成訂單**（依日期 1/15, 1/20, 2/05, 2/18, 3/10, 3/22 嚴格升冪排列）。
  > 💡 **防呆防錯檢驗**：Q1 資料庫中總共有 7 筆訂單（含 1 筆 `CANCELLED` 的 ORD-2024-005）。若漏寫 `status = 'COMPLETED'` 會查出 7 筆；若漏寫 `ORDER BY order_date ASC`，2/18 會排在 2/05 前面。這兩個條件缺一不可！
  >

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT order_number, order_date, total_amount 
FROM orders 
WHERE order_date BETWEEN '2024-01-01' AND '2024-03-31'
  AND status = 'COMPLETED'
ORDER BY order_date ASC;
```

</details>

### Q8. 列出所有客戶所在的城市，且結果不可有重複值

- **商業場景**：物流團隊需要評估目前車隊配送已覆蓋了哪些縣市。
- **思考提示**：使用 `DISTINCT` 去重，並排除 `IS NOT NULL`。

### Q9. 查詢客戶名稱中包含 'Tech' 或 'Labs'（不區分大小寫）的客戶列表

- **商業場景**：高科技新創專案小組需要盤點名下帶有科技標籤的企業客戶。
- **思考提示**：使用萬用字元 `%` 與 PostgreSQL 不分大小寫匹配 `ILIKE`。
- **預期產出**：共 **3 筆** 客戶（Apex Semi Tech, Future AI Labs, Horizon BioTech）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT company_name, industry 
FROM customers 
WHERE company_name ILIKE '%Tech%' OR company_name ILIKE '%Labs%';
```

- **核心解說**：標準 SQL 為 `LIKE`（區分大小寫），PostgreSQL 特有的 `ILIKE` 能避免漏查小寫 tech 的情況。

</details>

### Q10. 計算每項產品的毛利率（(unit_price - cost_price) / unit_price），命名為 gross_margin_rate_percent

- **商業場景**：產品經理評估各品項的獲利體質，抓出高利潤商品。
- **思考提示**：在 `SELECT` 中直接進行算術運算，並可用 `ROUND()` 格式化小數位數。
- **預期產出**：共 **6 筆** 產品，以毛利率最高排到最低（最高為 Data Analytics Suite 84.21%）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    product_name,
    unit_price,
    cost_price,
    ROUND((unit_price - cost_price) / unit_price * 100, 2) AS gross_margin_rate_percent
FROM products 
ORDER BY gross_margin_rate_percent DESC;
```

</details>

### Q11. 統計目前有效 (ACTIVE) 客戶的總數、最高信用額度與平均信用額度

- **商業場景**：董事會年度報告需要整體的有效客戶總覽指標。
- **思考提示**：使用 `COUNT(*)`, `MAX()`, `AVG()` 配合 `WHERE status = 'ACTIVE'`。
- **預期產出**：1 筆統計結果（total: 8, max: 1000000.00, avg: 568750.00）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    COUNT(*) AS total_active_customers,
    MAX(credit_limit) AS max_credit_limit,
    ROUND(AVG(credit_limit), 2) AS avg_credit_limit
FROM customers 
WHERE status = 'ACTIVE';
```

</details>

### Q12. 統計每個地區 (region) 的業務員人數與平均月業績目標 (monthly_target)

- **商業場景**：HR 與業務副總需要評估各區業務配比與目標權重。
- **思考提示**：以 `region` 進行 `GROUP BY` 分組。
- **預期產出**：共 **3 個地區**（North: 2人, South: 2人, Central: 1人）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    region,
    COUNT(salesperson_id) AS salesperson_count,
    ROUND(AVG(monthly_target), 2) AS avg_target
FROM salespeople 
GROUP BY region;
```

</details>

### Q13. 統計每個產品類別 (category) 的產品總數與平均毛利額 (unit_price - cost_price)

- **商業場景**：盤點硬體、軟體、資安與服務四種類別的產品線陣容與利潤空間。
- **思考提示**：分組 `GROUP BY category`，並對價差求 `AVG()`。
- **預期產出**：共 **4 種類別**（Hardware: 2件, Software: 2件, Security: 1件, Service: 1件）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
    category,
    COUNT(*) AS product_count,

GROUP BY category;
```

### Q14. 統計各業務員編號 (salesperson_id) 的已完成訂單總金額與筆數，並依總金額由高到低排序

- **商業場景**：業務部門週會需要快速盤點每位業務同仁目前的實收戰績排行榜。
- **思考提示**：查詢 `orders` 表，使用 `WHERE status = 'COMPLETED'` 過濾無效訂單，再以 `salesperson_id` 進行 `GROUP BY` 分組加總與計數，最後依總金額降冪排序。
- **預期產出**：共 **4 位業務員**（1號業務 6筆 $1,520,000 最高，2號業務 2筆 $140,000 最低）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    salesperson_id,
    COUNT(*) AS completed_orders_count,
    SUM(total_amount) AS total_revenue
FROM orders 
WHERE status = 'COMPLETED'
GROUP BY salesperson_id
ORDER BY total_revenue DESC;
```

</details>

### Q15. 找出下單總金額累計超過 300,000 的客戶編號 (customer_id) 與總金額

- **商業場景**：篩選出符合進入年度 VIP 俱樂部的優質買家。
- **思考提示**：對分組加總後的數字進行篩選，必須使用 `HAVING`！
- **預期產出**：共 **1 筆**（customer_id 1，累計消費 1,100,000.00）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    customer_id,
    SUM(total_amount) AS customer_total_spend
FROM orders 
WHERE status = 'COMPLETED'
GROUP BY customer_id
HAVING SUM(total_amount) > 300000
ORDER BY customer_total_spend DESC;
```

- **核心解說**：不可在 `WHERE` 裡面寫 `WHERE SUM(total_amount) > 300000`，因為聚合篩選必須在 `HAVING` 執行。

</details>

### Q16. 找出負責客戶數量超過 2 家的業務員編號 (salesperson_id) 與其客戶數

- **商業場景**：負載平衡審查：找出目前客戶量偏多的業務員。
- **思考提示**：在 `customers` 表中依 `salesperson_id` 分組，並用 `HAVING COUNT(*) > 2`。
- **預期產出**：共 **2 位業務員**（salesperson_id 1 與 2，各負責 3 家客戶）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    salesperson_id,
    COUNT(customer_id) AS client_count
FROM customers 
WHERE salesperson_id IS NOT NULL
GROUP BY salesperson_id
HAVING COUNT(customer_id) > 2;
```

</details>

### Q17. 將客戶依信用額度分類為「高額度(>=50萬)」、「中額度(20-50萬)」、「一般(<20萬)」

- **商業場景**：依據信用等級設定不同的合約審核流程。
- **思考提示**：使用 `CASE WHEN ... THEN ... ELSE ... END` 建立虛擬分類欄位。
- **預期產出**：全部 **10 家客戶** 均附帶其所屬 `credit_tier` 標籤。

<details>

```sql
SELECT 
    company_name,
    credit_limit,
    CASE 
        WHEN credit_limit >= 500000 THEN 'High Credit Tier'
        WHEN credit_limit >= 200000 THEN 'Mid Credit Tier'
        ELSE 'Standard Tier'
    END AS credit_tier
FROM customers;
```

</details>

### Q18. 統計各信用等級 (credit_tier) 的客戶家數

- **商業場景**：高階管理層想看全體客戶的信用金字塔分佈。
- **思考提示**：將 `CASE WHEN` 表達式直接放進 `GROUP BY` 之中。
- **預期產出**：共 **3 階層**（Mid Credit Tier: 6家, High Credit Tier: 3家, Standard Tier: 1家）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    CASE 
        WHEN credit_limit >= 500000 THEN 'High Credit Tier'
        WHEN credit_limit >= 200000 THEN 'Mid Credit Tier'
        ELSE 'Standard Tier'
    END AS credit_tier,
    COUNT(*) AS customer_count
FROM customers 
GROUP BY 
    CASE 
        WHEN credit_limit >= 500000 THEN 'High Credit Tier'
        WHEN credit_limit >= 200000 THEN 'Mid Credit Tier'
        ELSE 'Standard Tier'
    END
ORDER BY customer_count DESC;
```

</details>

### Q21. 列出所有訂單的訂單號碼、下單日期、客戶公司全名與負責業務員姓名

- **商業場景**：訂單管理後台主清單：必須同時看見買家是誰、誰簽回的單。
- **思考提示**：三表關聯：`orders` 關聯 `customers`，再關聯 `salespeople`。
- **預期產出**：共 **13 筆訂單明細**（依下單日期新到舊排序）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    o.order_number,
    o.order_date,
    c.company_name,
    s.name AS salesperson_name,
    o.total_amount
FROM orders o
INNER JOIN customers c ON o.customer_id = c.customer_id
INNER JOIN salespeople s ON o.salesperson_id = s.salesperson_id
ORDER BY o.order_date DESC;
```

</details>

### Q22. 找出「從未下過任何訂單」的客戶公司名稱與負責業務員

- **商業場景**：業務主管指派「喚醒休眠名單」：找出已經簽約建立資料卻從未下單的潛在客戶。
- **思考提示**：以 `customers` 為左表進行 `LEFT JOIN orders`，並找出右表訂單 ID 不存在的資料 (`WHERE o.order_id IS NULL`)。
- **預期產出**：共 **2 家客戶**（InnoVibe Studio 業務 David Ho、Jovial Media Group 業務 Betty Lin）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    c.company_name,
    c.city,
    s.name AS assigned_salesperson
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
LEFT JOIN salespeople s ON c.salesperson_id = s.salesperson_id
WHERE o.order_id IS NULL;
```

- **核心解說**：經典的「反向排除查詢 (Anti-Join)」。只有 `LEFT JOIN` 才能保留沒有訂單的客戶。

</details>

### Q23. 統計每位業務員的累積已完成業績總額，若該業務員未開單則顯示 0

- **商業場景**：業務個人績效儀表板 (KPI Dashboard)。
- **思考提示**：業務員為左表，`LEFT JOIN orders` 時必須在 `ON` 條件或篩選中注意只加總 `COMPLETED` 的訂單。
- **預期產出**：全部 **5 位業務員**（Alex Chen $1,520,000 最高，Eva Chang $0.00）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    s.name AS salesperson_name,
    s.region,
    s.monthly_target,
    COALESCE(SUM(o.total_amount), 0) AS actual_revenue
FROM salespeople s
LEFT JOIN orders o ON s.salesperson_id = o.salesperson_id AND o.status = 'COMPLETED'
GROUP BY s.salesperson_id, s.name, s.region, s.monthly_target
ORDER BY actual_revenue DESC;
```

### Q29. 比較每位業務員的業績是否達到其設定的 monthly_target（輸出：達標 / 未達標）

- **商業場景**：業務激勵獎金計算自動化。
- **思考提示**：結合 `LEFT JOIN`、`GROUP BY` 與 `CASE WHEN` 進行動態標籤判斷。
- **預期產出**：5 位業務中，Alex Chen 顯示 `Target Achieved 🎉`，其餘 4 位顯示 `Needs Improvement ⚠️`。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    s.name,
    s.monthly_target,

    CASE 
        WHEN COALESCE(SUM(o.total_amount), 0) >= s.monthly_target THEN 'Target Achieved 🎉'
```

### Q30. 綜合商業報表：產出每個城市的客戶總數、已下單客戶數、總營收與客戶平均貢獻度 (ARPU)

- **商業場景**：高階主管經營決策會議 (Executive Dashboard) 終極多維度報表。
- **思考提示**：運用 `COUNT(DISTINCT ...)`, `COALESCE`, `NULLIF` 進行精準指標計算。
- **預期產出**：共 **6 個城市** 之多維度指標（新竹 ARPU 110萬最高，台南為 0）。

<details>
<summary>🔍 點擊展開：解題思路與參考解答</summary>

```sql
SELECT 
    c.city,
    COUNT(DISTINCT c.customer_id) AS total_customers,
    COUNT(DISTINCT o.customer_id) AS active_buying_customers,
    COALESCE(SUM(o.total_amount), 0) AS city_total_revenue,
    ROUND(
        COALESCE(SUM(o.total_amount), 0) / NULLIF(COUNT(DISTINCT c.customer_id), 0), 
        2
    ) AS arpu_per_customer
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id AND o.status = 'COMPLETED'
WHERE c.city IS NOT NULL
GROUP BY c.city 
ORDER BY city_total_revenue DESC;
```

- **核心解說**：`NULLIF(..., 0)` 是一流工程師必備的防護技巧，能避免當某城市客戶數為 0 時觸發除以零 (Division by zero) 的系統崩潰。

</details>
