## 每天的 AI 協作方式（遵照 09 工作流）

```
做 SQL 題的黃金 6 步驟：

1. 讀題，自己拆解邏輯（利用 04 框架確認 Grain，2–5 分鐘）
2. 自己在 DBeaver 寫出 SQL（哪怕不完整，絕對不要直接問 AI）
3. 執行，看結果筆數與數字是否符合預期
4. 如果卡住超過 15 分鐘，向 AI 發問標準提示詞：
   「我的解題思路是 [說你的想法]，但我寫出的 SQL 是 [貼你的 SQL]，
    目前的報錯/結果是 [貼結果]，請問我哪裡的邏輯有盲點？」
5. 理解 AI 的反饋，自己重新在 DBeaver 敲出正確版本
6. 在筆記中記下一句話：「這道題學到的商業邏輯與陷阱」
```

## Git Commit 規範（從 M1 養成工程習慣）

```
格式：<type>: <簡短任務說明>

常用類型：
feat:     新增練習解答或功能（例：feat: M1 商業題庫 Q01-Q10 完成）
fix:      修正錯誤的 SQL 邏輯（例: fix: M1 修復訂單多對多重覆計算 Bug）
docs:     筆記、心得、README 更新（例: docs: M1 學習心得與 Checkpoint 整理）
refactor: 重構優化 SQL 寫法（例: refactor: 將 WHERE 改寫為高效 JOIN）
```
