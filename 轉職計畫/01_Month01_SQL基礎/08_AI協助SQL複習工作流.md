# 08 — AI 協助 SQL 複習工作流（你的 24 小時隨身助教）

> **「用 AI 學 SQL」和「讓 AI 寫 SQL」是完全不同的事。**
> 前者讓你越來越強，後者讓你越來越依賴。

---

## 核心原則

```
❌ 錯誤用法：題目 → AI → 複製答案 → 下一題

✅ 正確用法：題目 → 自己想 → 自己寫 → AI Review → 理解差異 → 改進
```

**AI 是你的 Code Reviewer，不是你的代寫機器。**

---

## 三階段學習流程

### 階段 1 — 獨立思考（20 分鐘）

```
1. 讀題
2. 用「SQL 問題拆解框架」填表（參考 [07_SQL商業問題拆解框架.md](./07_SQL商業問題拆解框架.md)）
3. 自己寫 SQL（哪怕不完整）
4. 執行，看結果
5. 如果結果不對，嘗試 Debug（至少 10 分鐘）
```

**超過 20 分鐘卡住才問 AI，而且不是問「答案是什麼」。**

---

### 階段 2 — AI 協助（問對問題）

#### ✅ 好的提問方式

**方式 A：引導式 Hint**
```
我在解這個 SQL 題目：
[題目描述]

我的思路是：[你的想法]
我寫出的 SQL 是：[你的 SQL]
執行結果是：[結果]
但我預期應該是：[預期]

請不要給我最終答案。
只告訴我：
1. 我的思路方向對嗎？
2. 哪個部分的邏輯有問題？
3. 給我一個 Hint，讓我自己修正
```

**方式 B：Compare & Explain（做完後）**
```
我已經完成這道 SQL 題：
我的解法：[你的 SQL]
你的建議解法：[讓 AI 給一個版本]

請比較兩個版本：
1. 哪個效能更好？為什麼？
2. 哪個可讀性更好？為什麼？
3. 我的版本有沒有潛在問題？
4. 有沒有更優雅的寫法？
```

**方式 C：Debug 協助**
```
這條 SQL 的結果不對：
SQL：[你的 SQL]
實際結果：[結果]
預期結果：[預期]
資料表結構：[描述]

請幫我找出邏輯問題在哪裡（不要直接給我修正後的 SQL，先給分析）。
```

#### ❌ 避免的提問方式

```
❌ 「幫我寫一條找出 VIP 客戶的 SQL」
❌ 「這題怎麼寫？」
❌ 「給我第 15 題的答案」
```

### 階段 3 — 記錄學習軌跡

每次 AI Review 後，填寫以下模板，存入 `my_solutions/`：

```sql
-- ============================================================
-- 題目 [編號]：[題目名稱]
-- 難度：Level [1-5]
-- 完成日期：YYYY-MM-DD
-- ============================================================

-- 【第一次嘗試】
-- 我的思路：[說明你的想法]

SELECT ...  -- 你的第一版

-- 執行結果：[描述結果]
-- 問題：[哪裡不對？]

-- ============================================================
-- 【Debug 過程】
-- ============================================================
-- 發現問題：[什麼問題？]
-- 修正方向：[怎麼想的？]

-- 修正後：
SELECT ...

-- ============================================================
-- 【最終版本】
-- ============================================================

SELECT ...

-- ============================================================
-- 【AI Review 後的改進】
-- AI 指出：[AI 說了什麼]
-- 我學到：[你的理解]
-- 改進後：
-- ============================================================

SELECT ...  -- 最終最優版本

-- ============================================================
-- 【這題學到的重點】
-- 1. [學習點 1]
-- 2. [學習點 2]
-- ============================================================
```

## 月底 AI 總結練習

Month 01 結束時進行一次測試：

```
回顧這個月所有題目，對 AI 說：

「我這個月學了 SQL 基礎，包含 SELECT、JOIN、GROUP BY、CASE WHEN。
請出 5 道中等難度的 B2B 商業 SQL 題，不要給答案，
讓我自己解，之後再給我 Review。」

用這 5 道題測試自己真實的 SQL 水準。
```

---

## AI 的限制：你必須自己判斷的事

| AI 能做到的 | 你必須自己判斷的 |
|:---|:---|
| 生成語法正確的 SQL | 結果是否符合商業邏輯 |
| 指出 Syntax Error | Data Grain 是否正確 |
| 提供效能優化建議 | 資料是否有品質問題 |
| 解釋 SQL 執行順序 | NULL 在你的業務中代表什麼意義 |
| 比較不同寫法的優劣 | customer_id 在這個系統是否唯一 |

**Domain Knowledge + Data Understanding = 你的核心價值**

## 實用 Prompt 範本速查

### Review 我的 SQL
```
Review 這條 SQL，指出：效能問題、邏輯問題、可讀性問題、潛在 Bug：
[你的 SQL]
```

### 出練習題
```
出 3 道關於 [主題] 的 B2B SQL 練習題，難度中等，不要給答案。
情境設定：一個 B2B 企業客戶管理系統，有 customers、orders、order_items、salespeople 表。
```

### Hint 模式
```
我在解這道 SQL 題，卡住了。
題目：[題目]
我的想法：[你的思路]
請只給 Hint，不要直接給答案。
```

### Compare 兩個 SQL
```
比較這兩條 SQL 的優劣（效能、可讀性、正確性）：
版本 A：[SQL A]
版本 B：[SQL B]
情境：[資料量大小、使用場合]
```
